# 系统总览

> 状态：当前
> 最后更新：2026-11-04
> 目标读者：开发、测试、运维、接手人

WellRead Personal 是单 owner、本地部署的个人知识库与阅读助手：把文档导入、检索问答、交互式精读、个人技能与 MCP 外部接入放在同一套服务里。数据留在本机，不依赖外部 SaaS。

## 1. 服务生态

| 服务 | 目录 | 职责 | 端口 |
|---|---|---|---|
| frontend | `frontend/` | Vue 3 SPA；问答、知识库、精读、技能、设置 | 6151 |
| app | `app/` | Go 后端：认证、知识库、文档、会话、精读、技能、MCP Key、设置 | 6152 |
| docreader | `app/docreader/` | 文档解析 gRPC 服务 | 内部 50051 |
| ylsw | `rag/` | 检索/生成侧车：嵌入、FAISS/BM25、融合、重排、答案生成 | 内部 5000 |
| postgres | `deployments/` | 业务库（知识库、文档、会话、精读、技能、配置） | 内部 5432 |
| redis | `deployments/` | 队列、缓存、流式状态 | 内部 6379 |

外部 MySQL 仅由 ylsw 用于分块/Text2SQL；语料、BGE 模型和 FAISS 索引在 `data/rag/`（gitignore）。

## 2. 身份与访问

- 只有一个 owner。首次启动由 `OWNER_EMAIL` / `OWNER_PASSWORD` 创建；已存在则不重复建号。
- 保留一条内部 tenant 作为业务归属；用户看不到、也不能切换工作区。
- 前端使用 JWT 登录；MCP/CLI 使用设置页生成的单只读 API Key。
- 没有角色、能力码、部门、共享空间、ACL、CR 或治理台。
- 后端是安全边界：除登录、健康检查与静态资源外，所有接口都要求认证。

## 3. 核心链路

### 3.1 启动与登录

1. app 启动读取 `OWNER_EMAIL` / `OWNER_PASSWORD`，缺失或密码不合规直接失败。
2. 自动迁移单基线 schema；已有 owner 则跳过创建。
3. 前端邮箱 + 密码登录，进入 `/platform/creatChat`。

### 3.2 入库

1. 前端上传文件、网页或手工 Markdown，或添加本地目录/Git 代码项目。
2. app 解析、分块、提取元数据，写入 PostgreSQL。
3. app 调用 ylsw `/ingest`，只传 App 生成的 chunks；ylsw 做嵌入、FAISS/BM25 索引。
4. 解析/索引状态在知识库详情与处理时间线中展示。

### 3.3 问答

1. 前端创建会话，默认检索全部知识库，可限定单库。
2. app 组装检索请求调用 ylsw `/search` 或 `/chat/stream`。
3. ylsw 做四路召回、融合、精排、上下文组装与答案生成。
4. app 返回流式答案与可定位引用；引用可打开文档/分块/精读。

### 3.4 精读

1. 从文档或引用进入精读工作台。
2. app 生成阅读计划，按章节读取、提问、记录笔记，最终生成报告与导出。
3. 精读固定使用 `grill-with-docs`，不共享普通问答的可执行技能工具。

### 3.5 技能与外部接入

- 技能是 owner 的个人资产，可创建、编辑、启停、删除；普通问答时按需注入。
- 单只读 API Key 供 MCP/CLI 使用；MCP 固定 17 个只读工具，不提供写入、删除、建库、模型或租户管理。

## 4. 数据归属

| 数据 | 位置 |
|---|---|
| 知识库、文档、分块、版本、会话、精读、技能、配置 | PostgreSQL |
| RAG chunks / 表格 | 外部 MySQL（`YLSW_Service_Table`） |
| 向量与 BM25 索引 | `data/rag/faiss_index.bin` 等（gitignore） |
| 上传文件 | `data-files` volume / 本地存储目录 |
| 语料、BGE 模型 | `data/rag/Data`、`data/rag/models` |

个人版要求全新数据库；企业库不原地升级。删除知识库会删除其文档、版本、索引与精读关联。

## 5. 保留与删除边界

保留：多知识库、文件夹、标签、上传/网页/手工/代码项目入库、解析状态、自动版本快照与回滚、问答与引用、精读、技能、MCP/CLI 只读接入、模型/解析/存储/提示词设置、健康与队列。

删除：注册、邀请、OIDC、多账号、租户切换、部门、角色、能力契约、共享空间、KB/文档 ACL、CR/评论/审批、治理台、审计导出、文档生效/废止日期、多 Key 与 KB 白名单。

## 6. 部署形态

- 六服务 compose：`deployments/docker-compose.yml`；项目名固定 `app`，沿用命名卷。
- 本机默认只暴露 frontend 6151 与 app 6152；其余服务只在 Docker 内网。
- 环境变量集中在 `deployments/.env`，示例见 `.env.example`。
- 生产/长期使用前必须配置 owner、数据库口令、`JWT_SECRET`、`SYSTEM_AES_KEY` 与模型密钥。
