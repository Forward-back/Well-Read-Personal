# 精读 · 答辩问答

> 用途：答辩 Q&A 速查。
> 核心口径：**精读不是摘要，是受控的阅读循环：读窗口 → 提问 → 自答 → 矛盾检测 → 沉淀；只读、可停、可追溯。**
> 优先准备：Q1（和问答/长上下文区别）、Q6（五拍）、Q7（事实/决策分流）、Q9（三道门）、Q12（自答检索）、Q13（每轮暂停）、Q24（评测）。

## 一、定位与策略

### Q1：精读和普通问答、直接把全文塞给模型有什么区别？

普通问答是“召回几个片段再回答”，回答范围由检索决定；精读是用户显式选择 1–5 篇文档，按章节逐轮读完，边读边问、边沉淀。

和“全文塞模型”相比：

- 精读有固定动作集、步数和 token 预算，不开放外部搜索/任意工具；
- 每轮有阅读窗口、问题、证据和结论，过程可暂停、可恢复、可追溯；
- 报告由结构化四表投影，不是一次生成的摘要；
- 权限、引用、版本和审计都在链路里。

一句话：问答解决“找一段”，精读解决“读完一批并形成可复核的结论”。

### Q2：为什么固定 grill-with-docs，不让部门选技能？

精读要的是**稳定的审问纪律**，不是问答风格的随机变化：

- 固定策略保证每轮都做“读窗口、提问、自答、矛盾、沉淀”，不被部门技能改写；
- 技能面向普通问答的提示注入，和精读的可执行动作集是两套东西；
- 固定策略才能做统一评测、审计和问题质量门槛。

代价是灵活性：不能按部门定制精读话术；换策略需要改内置策略并重新评测，不走技能配置。

### Q3：精读会修改文档吗？和协作 CR 是什么关系？

不会。精读是**只读**：

- 不写文档、不写 CR、不改 ACL/共享；
- 选中文档之外的内容不引入；
- 报告是阅读产物，不是正式文档变更。

要改文档，走协作 CR；精读报告可以作为修改依据，但不会自动回写正文。

### Q4：为什么一次只能一个 KB、最多 5 篇？跨 KB 行不行？

当前限制是产品边界，不是技术做不到：

- 一个 KB 保证权限、ACL、密级和检索口径一致；
- 5 篇控制 token、时间和问题密度，避免“读不完还硬读”；
- 跨 KB 会引入不同共享/ACL/部门规则，当前先不做。

大文档可以读，但受窗口和预算约束；跨 KB/更多文档是待评估需求，不是已支持能力。

### Q5：三档深度具体差在哪？为什么不能中途切换？

- 快速通读：窗口大（约 8000 字符）、问题少、自动推进，适合先判断值不值得细读；
- 标准：约 4000 字符窗口，关键节点确认，多数制度/合同用这档；
- 逐条精读：约 1500 字符窗口，术语、条件、例外、数值逐项核对，提问最密。

深度影响窗口、问题密度和 token 预算，不影响权限和文档范围。中途切换会让计划、预算和阅读纪律漂移，所以开始后固定；要换深度就新建一次精读。

## 二、引擎与质量

### Q6：每轮“五拍”是什么？真的每轮都有 2–4 个问题吗？

每轮固定：读本轮窗口 → 生成理解 + 问题 → 自答分流 → 矛盾检测 → 即时沉淀。

问题数目标是 2–4 个，但有两个约束：

- 质量门槛会丢掉泛问、无推荐解读的问题；
- 去重后可能少于 2 个。

所以我们不为了凑数造问题；“2–4”是上限和目标，不是硬性每轮必须四个。

### Q7：事实问题和决策问题怎么分？谁回答？

每个问题必须带 `kind`：

- **fact**：文档内可查，引擎强制检索并自动回答，附证据，标“推断”；
- **decision**：涉及取舍、口径、责任边界，必须用户裁定。

不是让模型自觉自答：引擎会对未解决的 fact 问题强制检索，检索到证据后单独让模型作答；检索不落才保留待确认。decision 不会自动替用户拍板。

### Q8：问题质量门槛是什么？泛问怎么过滤？

问题必须满足：

- 带 `kind`（fact/decision）和 `gap_type`（歧义/缺参数/矛盾/范围/版本）；
- 有推荐解读和依据；
- 指向文档缺口，不是“主要内容是什么”这类泛问。

引擎会丢弃泛问、无推荐答案的问题。默认审问目标是：含糊表述、缺失参数、跨章节/跨文档矛盾、版本失效风险。

### Q9：怎么防止模型编造结论？“三道门”是什么？

结论必须同时过三道门，才能从候选变已确认：

1. **引用充分**：至少一个证据 chunk，属于选中文档、当前可读、能定位到章节和原文；
2. **无冲突**：和已确认结论、术语不矛盾；
3. **跨文档一致**：同一事实多篇文档口径一致；不一致转矛盾，请用户裁定。

未过门的结论停在候选，进入报告“未决/待确认”，不能伪装成已确认事实。自动回答也要过门，并标“推断”。

### Q10：引用证据怎么校验？chunk 不存在或越权怎么办？

每条证据必须有 chunk ID 和逐字引文；引擎校验：

- chunk 是否属于本次选中文档；
- 当前 ACL/密级是否仍可读；
- 引文是否在该 chunk 中逐字存在。

任何一条不满足，该结论不能过门；精读开始、读取、导出都会复核权限。失权文档不静默过滤，而是暂停并要求移除，避免“少读了一篇还以为读完了”。

### Q11：矛盾检测可靠吗？A/B 裁定后结论怎么变？

当前以**模型自报 + 引用校验**为主：矛盾必须给冲突双方出处；没有双出处的不算矛盾。

矛盾会进矛盾表，右栏展示 A/B 两列原文；用户可选择以 A 为准、以 B 为准或自定义裁定。选择一边后，支持该边的结论提升为已确认，裁定写入用户裁定。

边界：模型可能漏报矛盾，embedding 只做状态摘要相关性预筛，不做矛盾判定；不能承诺召回所有冲突。

### Q12：自答检索怎么限定在选中文档？语义检索失败怎么办？

精读自答只在本次选中文档内检索：

- 优先走 YLSW `/search` 的 `document_ids` 白名单，语义 top3 + 关键词结果合并；
- 结果还要按选中文档的 chunk 再校验；
- YLSW 不可用或结果无法映射时，回退关键词检索；
- 不跨 KB、不引外部资料。

检索不落就保留待确认，不拿库外内容硬答。

### Q13：为什么标准/逐条精读每轮都暂停？快速通读为什么不？

标准/逐条精读的目标是“边读边确认”，每轮暂停让用户看思考链路、问题和沉淀，再决定继续；否则会退化成批量摘要。

快速通读是“先判断值不值得细读”，允许自动推进，只在关键节点或用户停止时暂停。

暂停不是卡住：已完成轮次、四表数据、阅读进度都保留，点继续从下一轮接着走。

### Q14：步数、token 预算怎么控？超了怎么办？

按轮和按 run 双层预算：每轮有最大检索次数、问题数、窗口大小；整个 run 有最大步数和 token 预算。

超预算时暂停并说明原因，不静默降级、不拼接未过滤全文；用户可以继续/停止/新建。快速/标准/逐条的预算不同，深度是预算的第一层控制。

### Q15：停止、恢复、模型失败怎么处理？会回退到普通 RAG 吗？

- 停止：保留已读进度、笔记、四表数据和引用，可恢复；
- 模型失败：暂停在当前步，可重试；不自动回退到普通 RAG；
- 不拼接未过滤全文，不编造结论；
- 文档被删除/权限收回：暂停并提示移除该文档后才能继续。

精读接受“慢”，但不接受“悄悄降级成另一个系统”。

## 三、思考链路与界面

### Q16：为什么精读模型必须支持思考模式？

精读要的是审问和矛盾检测，不是快速摘要；思考模式能提升问题质量和跨段推理，同时留下可回看的推理链路。

创建和每轮推进前都会校验模型的有效思考控制；不支持思考的模型直接拒绝，不静默降级。旧结构化 run 如果在用不支持思考的模型，推进时会懒迁移到租户当前精读模型。

代价是延迟和成本更高；精读本来就接受比问答慢。

### Q17：思考内容存在哪？会不会进报告/审计？会不会泄露？

每轮 reasoning 存在 step 的 `notes_patch.reasoning`，思考链路展示“读取窗口 → 模型思考 → 提问 → 检索与自答 → 沉淀”。

- 只在本次 run 的思考链路可见；
- 不进入报告正文、检索审计、JSON 导出；
- 但数据库里仍存，管理员直接读库能看到；不是端到端加密。

如果评委问隐私：这是内部单租户系统，按运行审计保留；对外分享报告不会带原始 reasoning。

### Q18：左栏全文、多文档切换、拖拽怎么做的？

左栏不是 chunk 列表，而是按 chunk 顺序拼接的完整文档：

- `/reading/runs/:id/documents` 逐文档复核 ACL 后返回全文；
- 多文档切换，当前轮文档自动跟随；
- 返回 section 的 UTF-16 偏移，前端高亮当前段并滚动到可视区；
- 左栏 220–640px 可拖拽，pointer + rAF + CSS 变量，双击复位，宽度按 localStorage 记忆；
- 移动端单列、禁用拖拽。

全文是 chunk 拼接文本，不是原始 PDF/DOCX 排版；大文档首屏和拖拽性能仍需专项压测。

### Q19：大文档性能怎么样？阅读模型会不会挤占普通问答？

大文档受窗口切分和预算控制，不会一次塞全文；但左栏全文渲染、拖拽重排和首字延迟还没有专项压测，这是待补项。

精读使用独立阅读模型配置，不走普通问答检索，也不回退普通 RAG；但底层模型服务容量仍共享，不能承诺物理隔离。模型不可用时精读不可用，不降级。

## 四、报告、版本与权限

### Q20：报告怎么生成？能编辑吗？并发版本怎么处理？

报告由四表投影生成：结论摘要、术语、矛盾、未决问题、引用、覆盖与局限；Markdown 给人和导出，JSON 给机读/二次处理。

报告可以整篇编辑：草稿单独存储，保存/重置带 `base_version` 乐观锁；版本冲突返回 409 并回载最新版。Markdown 导出优先用编辑草稿，JSON 仍以四表事实源为准。

继续阅读会使旧报告草稿失效，避免基于旧状态导出；需要重新生成/编辑。

### Q21：精读报告和文档版本、废止是什么关系？

精读报告引用的是阅读时的 chunk 证据，不是文档版本快照；报告本身是阅读产物，不修改文档版本。

- 废止文档：精读显式选中文档时仍可读（检索 include_expired），但问答默认剔除；
- 文档被编辑/重解析：进行中的精读会受权限/内容变化影响；报告里的证据按当时 chunk 保存；
- 历史回答的引用版本绑定是问答侧能力，不要把它说成精读自动绑定文档版本。

### Q22：权限、共享、ACL 在精读哪里生效？中途失权怎么办？

- 创建时逐个文档复核 KB/部门/共享/ACL/密级；任一文档无权，拒绝整个精读并提示移除；
- 每轮读取、全文接口、导出都重新复核；
- 共享入 KB 可精读，但只读；
- 中途失权/删除：暂停并要求移除，不静默过滤。

这是 fail-closed：宁可停下，不带着“少一篇”的上下文继续生成结论。

### Q23：历史精读 run 怎么兼容？旧数据怎么办？

历史 run 的 notes 继续只读展示；完工的历史 run 首次读取时懒迁移到四表（结论标“历史笔记”、无结构化出处；术语/问题/矛盾迁移），并提供运维批量迁移接口。

活动/停止的旧 run 保留旧渲染，不强行迁移；新 run 以四表为事实源。迁移只解决展示和统计，不伪造旧 run 的推理链。

## 五、评测与边界

### Q24：精读效果怎么评？人工盲评做了吗？

机器指标包括：

- 已确认结论引用覆盖率 100%；
- 矛盾双出处 100%；
- 可自答问题必须自答或给出未自答理由；
- 每轮问题数和“一次只问一个”；
- 全部 run 在步数/token 预算内，超限明确暂停；
- 权限 fail-closed、停止/恢复、导出失权拒绝回归。

**3 篇真实制度文档的人工盲评还没做**，性能压测、浏览器视觉验收、问题卡“纠正”UI 回归也未完成。答辩时不能把“未验收”说成“已验收”；正确说法是“机器指标和真实 API 冒烟已做，人工盲评待业务提供样本”。

### Q25：精读成本会不会很高？值得吗？

精读确实比问答慢、贵：多轮模型调用、思考模式、语义检索和证据校验都要成本。

但换来的是：全文覆盖、问题可追问、结论带出处、矛盾可裁定、报告可复核。对合同、制度、方案这类“读错代价高”的文档值得；对一句话事实查询不值得，应该用普通问答。

### Q26：这套精读什么时候不适用？

- 只需要查一个事实/一个数值：普通问答或 SQL 更快；
- 文档很短、一次就能读完：精读的多轮开销不划算；
- 需要实时低延迟：精读接受更慢，不适合实时客服；
- 需要修改文档：精读只读，改文档走 CR；
- 跨 KB/超过 5 篇/需要外部资料：当前不支持或明确禁止。

一句话：精读解决“读完一批文档并留下可复核结论”，不解决“快速查一条事实”。
