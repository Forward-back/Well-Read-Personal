# 个人版改造需求与范围

> 状态：规划
> 最后更新：2026-11-01
> 目标读者：产品、开发、测试
> 关联：[数据模型与认证](数据模型与认证.md)、[页面与提示词](页面与提示词.md)、[实施计划与验收](实施计划与验收.md)

## 1. 背景与目标

WellRead 当前是按公司内部单租户部署设计的企业知识库：六个角色、部门归属、知识库共享、文件夹与文档 ACL、CR 审批、治理看板与系统运维台共同构成权限与协作体系。个人版的代码仓库已经独立，目标是把它改造成一个人使用、本地部署、数据完全归自己的阅读与知识管理工具。

个人版要解决的不是“删掉几个菜单”，而是把系统的第一性原则从“组织内多人协作与授权”改成“单一所有者管理自己的知识”。所有围绕组织关系建立的数据结构、接口、页面和提示词都要退出主路径。

本轮的完成标准是“可日常使用”：在一台机器上用 Docker 启动，创建唯一所有者账号，能建知识库、导入文档、问答并看到引用、做交互式精读、维护个人技能、配置模型与外部接入，且界面上不再出现企业角色、部门、共享、ACL、治理与审批概念。检索算法与 RAG 索引结构的深度重做不纳入本轮，只清除其中的企业语义与过滤条件。

## 2. 已对齐的关键决策

| 主题 | 决策 |
|---|---|
| 身份 | 单账号登录，唯一 owner；不提供注册、邀请、OIDC、多账号切换 |
| 账号初始化 | 通过环境变量种子创建 owner，首次启动自动建号 |
| 运行形态 | 本地 Docker 单机部署，服务只绑定本机地址 |
| 权限内核 | 删除角色、能力契约、成员、部门、ACL、共享、CR 审批；只保留 owner 认证 |
| 租户模型 | 彻底删除租户与工作区字段，不再保留 `tenant_id` / `workspace_id` |
| 历史数据 | 全新数据库，历史账号、会话、审计、CR、部门数据全部丢弃 |
| 知识组织 | 保留多知识库、文件夹、标签；所有知识库归 owner 所有 |
| 协作 | 删除 CR、issue、评论、审批、reviewer、审计员；保留文档版本快照、对比与回滚 |
| 版本触发 | 文档保存前自动快照，重新解析前也快照；保留最近 50 个版本，可手动清理 |
| 文档生命周期 | 删除生效日期、废止日期与定时流转；保留手动归档与回收站恢复 |
| 问答范围 | 默认检索全部知识库，可切换为单个知识库 |
| 精读 | 保留完整精读工作台，删除 shared-in、逐文档 ACL 复核、部门聚合与阅读审计 |
| 技能 | 保留为个人技能库，删除部门归属、可见性能力与 per-skill 授权 |
| 外部接入 | 保留 MCP 与单一 owner API Key，删除 KB 白名单、多 Key 与能力授权 |
| 导航 | 五项扁平导航：问答、知识库、精读、技能、设置；登录后默认进问答 |
| 设置 | 五分区：账户与助手、模型与引擎、外部接入、系统健康与队列、关于 |
| 提示词 | 内置个人阅读助手提示词，删除企业话术；全局系统提示词可在设置中编辑 |
| 品牌 | 保留 WellRead 名称，个人版标识为 WellRead Personal |
| 代码策略 | 在个人版仓库 `main` 上彻底重构，不保留企业版兼容分支 |
| RAG 范围 | 本轮只去企业语义、权限过滤与提示词，不重做 chunk、索引和检索策略 |
| 验收 | 以“可日常使用”为准，要求构建通过并跑通核心人工流程 |

## 3. 目标用户与使用场景

个人版的用户只有一个人，同时承担“读者、知识库维护者、技术配置者”三种动作，但不再以角色区分。典型使用场景：

1. 第一次启动：填入 owner 邮箱与初始密码，登录后进入问答页。
2. 整理资料：创建多个知识库，按主题上传文档或录入网页，用文件夹与标签分类。
3. 阅读与提问：在问答页默认跨全部知识库检索，也可以限定某个知识库；回答必须带引用。
4. 深度阅读：从回答引用或知识库选中文档，进入精读工作台，按计划逐节阅读并形成笔记与报告。
5. 日常维护：编辑文档前系统自动留版本；误改后对比并回滚；不需要审批或协作。
6. 配置与接入：在设置里切换模型、解析器、存储与系统提示词；生成单一 API Key 供 MCP 客户端使用。
7. 本地排障：在设置的健康与队列分区查看服务状态、索引健康和失败任务。

## 4. 保留与删除范围

### 4.1 保留

- 问答：多轮会话、流式回答、引用与引用抽屉、历史会话、会话删除、检索 trace。
- 知识库：多库创建、复制、删除、基本信息、模型/解析/分块/图像/高级/存储/数据源配置。
- 文档：上传、网页导入、手工录入、解析状态、文件夹、标签、元数据、批量操作、归档与回收站。
- 版本：自动快照、版本列表、版本对比、回滚、版本保留上限与手动清理。
- 精读：阅读计划、三档深度、三栏工作台、自动推进、停止恢复、问题卡、笔记、报告、导出。
- 技能：个人技能目录、创建、编辑、启停、删除、问答时选择与注入。
- 外部接入：MCP 服务、单一 owner API Key、CLI 入口。
- 设置：模型与引擎、Ollama、解析器、存储后端、系统提示词、队列与健康、关于。
- 品牌：WellRead 名称与既有视觉语言，增加 Personal 标识。

### 4.2 删除

- 六角色与能力契约：`system_admin`、`company_admin`、`manager`、`knowledge_admin`、`editor`、`viewer`。
- 公司、部门、成员、邀请、部门角色、成员状态、租户切换。
- 共享空间、知识库共享、发布可见性、库内 ACL、文件夹/文档 allow/deny。
- CR 提交、审批、驳回、合并、关闭、reviewer、部门审计员、issue、评论、锚点评论、chunk 锁。
- 治理看板、公司/部门/系统审计、检索审计、审计导出。
- 文档生效日期、废止日期、生命周期定时流转。
- `/ops` 独立运维工作台、账号运维、平台 API Key 多 Key 管理、系统设置页中的成员与部门分区。
- 注册页、邀请注册、OIDC、工作区 onboarding、组织加入页。
- 企业提示词与文案中的公司、部门、员工、合规、授权、审批等表达。

## 5. 核心业务规则

1. 系统只有一个 owner。所有业务数据归 owner 所有，不存在“跨用户共享”或“跨部门可见”。
2. owner 登录后可访问全部页面与全部知识库；后端不再按资源计算可见性，只校验登录状态与 owner 身份。
3. 任何接口都不再接收 `acl_scope`、部门、角色或能力参数；RAG 侧也不应收到权限过滤上下文。
4. 知识库可以创建多个，但不存在共享关系；删除知识库会删除其文档、版本、索引与精读关联。
5. 文档编辑保存前自动生成版本快照；版本只保留最近 50 个，超出后删除最旧版本；重新解析前强制快照。
6. 归档文档默认不参与问答与精读检索；回收站中的文档不可检索，可恢复或彻底删除。
7. 问答默认跨全部知识库检索；选择单库时只检索该库；回答必须带可定位引用，引用不可编造。
8. 精读只能使用 owner 自己的文档；导出不再逐文档复核 ACL，覆盖范围直接按实际读取章节统计。
9. 技能是 owner 的个人资产，问答时可以选择启用技能；不存在部门技能、只读技能页或按人授权。
10. API Key 只有一把，可在设置中生成、查看掩码、重置与撤销；Key 不绑定知识库白名单，MCP 仍保持只读运行面。
11. 系统不记录员工原始问题，也不再提供治理用途的检索审计；运行日志只用于本地排障。
12. 所有服务默认只监听本机地址，不暴露公网；模型 Key、数据库口令与 owner 初始口令只来自环境变量。

## 6. 非目标

- 不做多用户、家庭共享、团队协作或 SaaS 多租户。
- 不保留企业版权限模型，也不做新旧角色兼容。
- 不迁移历史数据；旧库直接丢弃，RAG 语料后续重新入库。
- 不重做 chunk 策略、向量索引结构、四路召回算法与排序模型；这些留给后续独立阶段。
- 不做 Windows 桌面壳、移动端或浏览器插件。
- 不做公网部署、HTTPS 网关、SSO、OIDC 或组织目录集成。
- 不新增收藏、推荐、社交、分享链接等当前系统没有的个人功能。

## 7. 主要风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 权限概念贯穿前后端与 RAG | 漏删会产生隐藏依赖或运行时 403 | 先删权限内核与 schema，再逐个模块收口；全局搜索残留字段 |
| 数据库重置 | 历史数据不可恢复 | 改造前备份数据库与 `data/rag/`；新基线迁移与旧迁移分离 |
| RAG 侧企业过滤残留 | 检索为空或继续要求 scope | 先移除 `acl_scope`、部门/密级参数与 Text2SQL ACL，再重建索引 |
| 提示词残留企业话术 | 回答仍以“公司/部门/员工”视角组织 | 统一替换系统提示词、精读策略与技能模板，并做人工问答抽检 |
| 大范围删除代码 | 引用断裂、测试大面积失败 | 按后端、RAG、前端、文档四阶段推进，每阶段构建通过再进入下一阶段 |
| 单 Key 的暴露面 | 本机 Key 泄露可读全部知识 | 只绑定本机、Key 只显示一次并可随时撤销，MCP 保持只读 |

## 8. 验收摘要

个人版达到可日常使用，需要同时满足：

- 全新空库启动后，用环境变量种子账号登录，不出现注册、邀请或工作区选择。
- 侧栏只有问答、知识库、精读、技能、设置五项，默认落地问答。
- 问答默认全库检索并可切单库，回答带引用；精读可完成一次完整流程并导出。
- 知识库支持多库、文件夹、标签、上传/网页/手工、归档、回收站；文档编辑后可回滚到自动快照。
- 设置可完成模型、解析、存储、系统提示词、MCP Key 与健康检查。
- 全部页面与接口不再出现角色、部门、共享、ACL、治理、审批、审计概念。
- 前后端构建通过，RAG 语法检查通过，核心流程人工验收通过。

详细页面与提示词要求见[页面与提示词](页面与提示词.md)，数据与认证要求见[数据模型与认证](数据模型与认证.md)，实施顺序与验收清单见[实施计划与验收](实施计划与验收.md)。
