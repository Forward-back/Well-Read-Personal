# 数据模型与认证

> 状态：规划
> 最后更新：2026-11-01
> 目标读者：后端、RAG、前端、测试
> 关联：[需求与范围](需求与范围.md)、[页面与提示词](页面与提示词.md)、[实施计划与验收](实施计划与验收.md)

## 1. 目标

个人版的数据模型从“公司—部门—成员—角色—资源授权”收缩为“单一 owner 与他的知识资产”。认证只回答两个问题：请求是否来自 owner；owner 是否有权使用本机实例。业务层不再回答“这个用户能不能看这篇文档”。

本文件描述目标模型与拆除边界，不逐一罗列数据库字段；具体迁移脚本在实施阶段按本文原则编写。

## 2. 目标数据模型

### 2.1 核心实体

| 实体 | 含义 | 关系 |
|---|---|---|
| Owner | 唯一使用者与管理员 | 拥有全部知识库、技能、会话、精读、Key |
| Knowledge Base | 个人知识主题 | 归 owner；包含文件夹、文档、标签 |
| Folder | 知识库内目录 | 归知识库；无权限主体 |
| Document | 文档或网页快照 | 归知识库；有解析状态、归档状态、标签 |
| Document Version | 文档内容快照 | 归文档；自动生成，最多保留 50 个 |
| Chunk | 检索分块 | 归文档；与向量索引关联 |
| Session / Message | 问答会话与消息 | 归 owner；记录引用与检索 trace |
| Reading Run | 精读运行 | 归 owner；关联文档、章节、笔记、报告 |
| Skill | 个人技能 | 归 owner；问答时可选择注入 |
| Model Config | 模型与供应商配置 | 全局单份，归 owner 管理 |
| Engine / Storage Config | 解析器、向量引擎、存储后端配置 | 全局单份，归 owner 管理 |
| API Key | MCP 与 CLI 的唯一访问凭据 | 归 owner；只读运行面 |
| System Prompt | 全局助手提示词 | 全局单份，可编辑 |

### 2.2 实体规则

- 所有查询不再带租户、部门、成员或 ACL 条件；owner 是隐式的全局主体。
- 知识库、文档、技能、会话、精读不设 `department_id`、`tenant_id`、`workspace_id`、`visibility`、`share_scope`。
- 知识库不再有“共享给部门”“发布到门户”“库内 ACL”状态。
- 文档不再有“生效日期”“废止日期”“生命周期状态”；只保留草稿/解析中/可用/归档/回收站这类内容状态。
- 技能不再有部门归属、可见范围、只读标记或按人授权记录。
- API Key 不再关联能力码或知识库白名单；只有一把有效 Key。
- 审计与治理相关实体不进入个人版数据模型。

## 3. 需要删除的数据结构

以下概念与表应在新基线中消失；历史库不迁移，直接重建：

- 租户、工作区、公司、组织。
- 成员关系、成员状态、邀请、组织加入记录。
- 部门、部门角色、部门成员、部门审计员。
- 角色、能力码、能力契约、权限缓存。
- 知识库共享、发布可见性、共享空间视图数据。
- 库内 ACL、文档/文件夹授权主体、ACL 继承与 deny 记录。
- CR、CR 审批、CR reviewer、CR 合并记录、issue、评论、锚点评论、chunk 锁。
- 治理看板聚合数据、公司/部门/系统审计、检索审计与保留期配置。
- 文档生命周期日期与定时流转任务。
- 多 API Key、Key 能力范围、Key 知识库白名单。
- 注册、邀请注册、OIDC、工作区 onboarding 所需配置与记录。

删除时以“概念整体”为单位，不保留只为历史兼容的空表或空字段。若某表同时承载个人版仍需要的配置，应先拆分出目标表，再删除企业字段。

## 4. 认证与账号

### 4.1 Owner 初始化

- 通过环境变量提供 owner 邮箱与初始密码，例如 `OWNER_EMAIL`、`OWNER_PASSWORD`。
- 首次启动检测不到 owner 时自动创建；已存在则跳过，不覆盖密码。
- 不提供注册页、邀请注册、OIDC 登录、工作区创建与组织加入。
- 如环境变量缺失，启动失败并给出明确错误，不生成默认弱口令账号。

### 4.2 登录与会话

- 只保留密码登录与登出。
- 登录成功后直接进入问答页。
- 保留现有 token / session 机制作为本机认证基础，但 principal 只区分 owner；不再计算公司角色、部门角色或能力码。
- 登录响应不再返回 memberships、caps、tenant 切换信息或角色字段。
- 支持在设置页修改密码；修改后使旧会话失效或要求重新登录。
- 连续失败登录可保留基础限流；不引入复杂账号锁定流程。

### 4.3 安全边界

- 后端仍是安全边界：除登录、健康检查与静态资源外，所有接口都要求 owner 身份。
- 后端不信任前端传入的 owner 标识；owner 身份只来自认证中间件。
- 服务默认绑定 `127.0.0.1`；如用户显式改为对外监听，需自行承担风险。
- 模型 Key、数据库口令、owner 初始口令只来自环境变量，不写入数据库、日志或文档。
- MCP 使用的 API Key 视为 owner 授权，但 MCP 本身保持只读；不得通过 MCP 修改知识库或配置。

## 5. 资源访问规则

### 5.1 后端

- 新增统一的 owner 认证中间件，替换现有角色、能力、membership 与租户上下文中间件。
- 资源层不再计算部门归属、共享关系、ACL 结果或 CR 审批资格。
- 知识库、文档、版本、会话、精读、技能的查询与写入只校验 owner 身份和资源是否存在。
- 删除 `RequireCapability`、`RequireSystemAdmin`、租户上下文、membership 解析等中间件。
- API Key 认证独立于 owner 登录，但只授予 MCP 只读能力；不再按 capability 或 KB 白名单细分。

### 5.2 RAG 侧

- 请求不再携带 `acl_scope`、部门、角色、密级或用户标识。
- 检索、引用复核、导出前复核不再要求权限过滤。
- 删除 ACL 过滤模块、Text2SQL 的 ACL 分支与“缺 scope fail-closed”逻辑。
- 保留现有的四路召回、融合、重排与引用校验算法；只移除其中的企业过滤条件与参数。
- 索引元数据中的部门、密级、可见性字段删除；重建索引后不再写入这些字段。

### 5.3 MCP 与 CLI

- MCP 继续以只读方式暴露知识库检索与会话能力。
- 单一 API Key 可以访问全部个人知识库，不再配置白名单。
- Key 只显示一次，之后只显示掩码；支持重置与撤销。
- CLI 沿用 owner API Key，不再要求能力声明。

## 6. 数据初始化与迁移

### 6.1 全新基线

个人版不兼容旧数据库。建议：

1. 备份现有数据库与 `data/rag/`，确认备份可恢复。
2. 归档企业版迁移历史，不在旧迁移链上继续叠加个人版迁移。
3. 建立个人版单一基线迁移，直接创建目标 schema。
4. 清空开发数据库，按新基线初始化。
5. 清空向量索引并重新入库；旧索引中的部门与 ACL 元数据不保留。

### 6.2 数据保留边界

- 旧账号、会话、CR、审计、部门、共享、ACL 数据全部丢弃。
- `data/rag/` 中的原始语料文件可保留，但需要重新解析与建索引；旧索引文件不作为个人版数据源。
- 旧环境变量中的模型 Key、数据库口令可复用，但建议在改造后轮换。

### 6.3 回滚

改造前保留企业版代码与数据库备份。若个人版无法日常使用，允许回退到备份版本；个人版不做“双模型兼容”或运行时开关。

## 7. 当前实现与差距

| 当前实现 | 目标 | 差距 |
|---|---|---|
| 六角色、能力契约、membership、部门与 ACL 多层判定 | 仅 owner 认证 | 需删除权限内核与全部资源授权分支 |
| 所有业务表带租户/部门归属 | 无租户、无部门 | 需重建 schema 与迁移基线 |
| RAG 必须携带 `acl_scope`，缺省 fail-closed | 无权限过滤 | 需删除 ACL 过滤与 scope 校验 |
| 多 API Key 与能力/白名单 | 单 Key 只读 | 需重写 Key 管理 |
| 文档生命周期与定时流转 | 归档/回收站 | 需删日期字段与调度任务 |
| 审计与治理数据 | 不保留 | 需删除表、页面、接口与文档 |
| 注册、邀请、OIDC、工作区 onboarding | 种子 owner | 需删除入口与后端流程 |

## 8. 验收

- 空库启动时能用环境变量创建唯一 owner，并能登录、登出、改密码。
- 登录响应与前端状态中没有角色、membership、tenant、caps 字段。
- 所有业务接口只要求 owner 登录；不存在 `acl_scope` 参数或 ACL 失败分支。
- 数据库中不存在租户、部门、成员、角色、ACL、共享、CR、审计相关表与字段。
- RAG 请求与索引元数据中没有部门、密级、可见性字段。
- 单一 API Key 可完成 MCP 只读调用，撤销后立即失效。
- 旧库无法直接升级到个人版属于预期行为，并有明确的重建说明。
