> 本文件为个人版改造规划期依据，部分表述早于最终实现；当前实现以代码与 [系统总览](../01-项目总览/系统总览.md)、[当前进度](../03-进度与交接/当前进度.md) 为准。

## 1. 实施原则

1. 后端优先：先确立 owner 认证与新 schema，再改业务服务、RAG 与前端，避免前端先改后被旧接口拖回。
2. 概念整体删除：不保留空表、空字段、兼容分支或“企业版开关”。个人版不需要运行时切换。
3. 每阶段可构建：后端、RAG、前端每完成一块必须通过对应构建或语法检查，再进入下一块。
4. 先备份再破坏：数据库、`data/rag/`、当前提交与远程分支状态先确认；删除企业模块的提交单独可回退。
5. 文档跟随代码：企业文档不作为当前实现依据；改造完成后统一重写或删除，不留下相互矛盾的说明。

## 2. 阶段划分

### 阶段 0：冻结与备份

目标：确保彻底重构可回退。

- 确认当前分支、未提交改动与远程 `origin` 为个人仓库。
- 备份数据库与 `data/rag/`；记录备份位置与恢复方式。
- 为企业版最后状态打标签，便于对照与回退。
- 清理构建产物与临时测试数据，确认 `.env`、模型 Key、数据库口令不进入提交。

完成标志：备份可用，工作区状态清楚，后续改造提交可以单独回滚。

### 阶段 1：后端认证与 schema 基线

目标：删掉权限内核，只留 owner。

主要范围：

- `app/contracts/capabilities.json` 与 `contracts.go`：删除能力契约与校验。
- 认证中间件：删除角色、能力、membership、部门与租户上下文；新增 owner 认证。
- 登录：只保留密码登录；登录响应移除 memberships、caps、tenant 与角色字段。
- owner 初始化：从环境变量读取邮箱与初始密码，首次启动建号；缺失则启动失败。
- 注册/邀请/OIDC/工作区 onboarding：删除后端接口与相关表。
- 数据库：归档旧迁移链，建立个人版单一基线迁移；删除租户、成员、部门、角色、能力、共享、ACL、CR、issue、治理、审计、生命周期相关表。
- 所有仍保留的业务表去除 `tenant_id`、`department_id`、`workspace_id` 等字段。
- 删除部门、成员、治理、共享、ACL、CR、审计相关服务与路由。

完成标志：

- 后端以全新空库启动并自动创建 owner。
- 登录响应与中间件中不存在角色、能力、membership、tenant 概念。
- `go build ./internal/...` 与 `go vet ./internal/...` 通过；Windows 下受 duckdb/gojieba 限制的部分按环境限制记录，不通过改业务代码规避。

### 阶段 2：业务服务收口

目标：保留的功能在无权限模型下正常工作。

#### 2.1 知识库与文档

- 删除知识库共享、发布、可见性、ACL、部门归属与生命周期字段。
- 合并知识库设置为个人版八个页签；所有页签归 owner。
- 文档保留上传、网页导入、手工录入、解析、文件夹、标签、批量操作。
- 新增/收口归档与回收站：归档不参与检索，回收站可恢复或彻底删除。
- 删除文档生效/废止日期与定时流转任务。

#### 2.2 版本

- 文档内容保存前自动生成版本快照；重新解析前也生成快照。
- 版本保留最近 50 个，超出删除最旧版本；支持手动清理。
- 保留版本列表、对比与回滚；删除 CR 合并/回滚依赖与审批状态。
- 回滚后重新推送索引，保持 chunk 与引用行为现有能力。

#### 2.3 精读

- 保留 ReadingRun、三档深度、三栏工作台、自动推进、停止恢复、问题卡、报告与导出。
- 删除 shared-in、逐文档 ACL 复核、部门聚合、阅读审计、管理员批量迁移。
- 导出覆盖统计改为按实际读取章节计算。

#### 2.4 技能

- 技能去部门化，归 owner。
- 删除只读技能、部门授权、per-skill grant 与公司只读视图。
- 问答技能选择器只列出个人已启用技能。

#### 2.5 设置与外部接入

- 将原 `/ops` 技术能力并入设置页五个分区：账户与助手、模型与引擎、外部接入、系统健康与队列、关于。
- 删除账号运维、成员/部门、系统审计、平台告警配置、双身份切换。
- API Key 收敛为单一 owner Key，去掉能力范围与知识库白名单；MCP 保持只读。
- 增加全局系统提示词读取、保存与恢复默认接口。

完成标志：核心业务服务不再引用被删除的权限实体；后端构建与相关单测通过。

### 阶段 3：RAG 去企业语义

目标：检索不再需要权限上下文，提示词改为个人助手。

- 删除 `acl_scope`、部门、角色、密级等请求参数与内部传递。
- 删除 ACL 过滤模块、四路召回中的权限过滤、引用复核中的 ACL 检查、Text2SQL 的 ACL 分支。
- 删除元数据中的部门、密级、可见性字段写入。
- 更新问答、指代改写、精读、导出与技能注入提示词，去除公司/部门/员工/合规/审批话术。
- 保留现有检索、融合、重排算法与引用校验结构，不重做索引策略。
- 清空旧索引并重新入库，确认索引只含个人版元数据。

完成标志：

- RAG 请求不需要 `acl_scope`，缺少权限参数不再导致失败。
- `cd rag && python -m compileall -q src` 通过。
- 以个人文档完成一次入库、问答引用与精读检索，结果正常。

### 阶段 4：前端改造

目标：五项导航与个人化页面落地。

- 重写路由：只保留登录、问答、知识库、精读、技能、设置。
- 删除共享空间、治理、管理、运维台、CR/issue、注册/邀请/OIDC/onboarding 页面与路由。
- 删除前端能力 store、能力判断、角色菜单过滤与 `required_caps`。
- 登录页去掉注册、邀请、OIDC、组织加入；登录后进入问答。
- 知识库页面删除共享/发布/ACL/生命周期入口；合并设置页签；接入归档、回收站与自动版本。
- 精读页面移除权限复核与部门聚合相关 UI。
- 技能页面改为个人技能库。
- 设置页按五分区重组；接入系统提示词编辑。
- 全局文案清理：删除企业术语，替换为个人阅读语境。
- 删除前端已无用的 API 模块、store、组件与测试。

完成标志：

- `cd frontend && npm run type-check`、`npm test`、`npm run build` 通过。
- 侧栏只有五项，登录后默认进入问答。
- 浏览器手工走查核心页面，无企业入口与术语残留。

### 阶段 5：文档与仓库收口

目标：文档只描述个人版，不保留相互矛盾的企业说明。

需要重写或更新：

- 根 `README.md`：改为 WellRead Personal 的定位、启动、数据目录与使用入口。
- `CLAUDE.md`：改为个人版操作指南，删除角色/权限/ACL/治理规则与命令中不再存在的部分。
- `docs/01-项目总览/系统总览.md`、`术语与约定.md`：改个人版，或合并进新文档。
- `docs/03-进度与交接/当前进度.md`：替换为个人版进度与验证基线。
- `app/README.md`、`frontend/README.md`、`rag/README.md`、`mcp/README.md`、`deployments/README.md`：删除角色、部门、共享、ACL 等企业说明。
- 各子系统文档中的企业接口、角色矩阵、治理说明同步删除或改写。

建议删除：

- `docs/02-需求与设计/角色与权限/` 全部文档。
- 治理台、协作审批、部门管理、企业管理相关的功能与界面文档。
- 演示答辩、企业演示脚本与截图索引中不再适用的内容。
- `docs/04-历史归档/` 可按“是否保留历史追溯”决定；若删除，先确认个人仓库已有备份。

执行要求：

- 文档删除放在代码改造稳定之后，避免过早丢失企业版对照信息。
- 删除与重写分开提交，提交信息说明范围。
- 新文档 `docs/个人版改造/` 作为个人版需求与实施依据；不新增重复的企业版说明。

完成标志：仓库内不再有把当前实现描述成企业多角色系统的文档入口。

## 3. 测试与验证

### 3.1 自动化

| 范围 | 命令/检查 | 说明 |
|---|---|---|
| 后端 | `go build ./internal/...`、`go vet ./internal/...` | Windows 下 duckdb/gojieba 限制按环境限制记录 |
| 后端单测 | 相关服务包 `go test` | 删除企业权限测试，补充 owner 认证与版本保留测试 |
| 前端 | `npm run type-check`、`npm test`、`npm run build` | 删除企业页面测试，补充五项导航与设置测试 |
| RAG | `python -m compileall -q src` | 另跑现有检索/ACL 删除后的回归测试 |
| MCP | `uv sync --extra test && uv run pytest -q` | 单 Key 只读调用 |
| 部署 | compose config 检查 | 确认端口只绑定本机，服务依赖完整 |

### 3.2 人工端到端

1. 空库 + 环境变量启动，自动创建 owner，登录成功。
2. 新建两个知识库，分别上传文档与网页，确认解析完成。
3. 问答默认全库命中两个库的文档；切换单库后只命中该库。
4. 打开引用文档，进入精读，完成一次快速深度并导出 Markdown/JSON。
5. 编辑文档，确认自动生成版本；回滚到上一版本并重新检索。
6. 归档文档，确认问答不再命中；从回收站恢复后重新命中。
7. 新建技能并在问答中选择，确认注入生效。
8. 设置中修改系统提示词、模型、解析器与存储；MCP 用单 Key 只读调用成功。
9. 全局搜索 UI 与提示词，确认无企业角色、部门、共享、ACL、治理、审批术语。

### 3.3 安全自查

- 服务只监听本机地址；对外暴露时有无明确说明。
- `.env`、模型 Key、数据库口令、owner 初始密码未进入 git、日志与文档。
- API Key 只显示掩码，撤销后旧 Key 立即失效。
- 删除注册/邀请/OIDC 后，不存在绕过登录的入口。
- 检索接口不再接受权限过滤参数，但也不存在未认证可调用的业务接口。

## 4. 验收清单

- [ ] 唯一 owner 可由环境变量初始化并登录，注册与邀请入口不存在。
- [ ] 数据库为个人版新基线，无租户、部门、成员、角色、ACL、共享、CR、审计表。
- [ ] 后端只校验 owner 登录，不计算角色与资源授权。
- [ ] 侧栏为问答、知识库、精读、技能、设置五项，默认进入问答。
- [ ] 多知识库、文件夹、标签、上传/网页/手工、归档、回收站可用。
- [ ] 文档保存自动快照，保留 50 个版本，可对比与回滚。
- [ ] 问答默认全库、可切单库，引用可用，历史会话可用。
- [ ] 精读完整流程可用，导出无权限复核内容。
- [ ] 个人技能可维护并在问答中选择。
- [ ] 设置五分区可用，模型/解析/存储/提示词/MCP Key/健康检查正常。
- [ ] RAG 无 `acl_scope`、部门与密级过滤；索引已重建。
- [ ] 前端、后端、RAG、MCP 构建或测试通过，异常见环境限制记录。
- [ ] 页面、提示词、日志与用户可见文档无企业术语。
- [ ] 备份与回退路径明确，改造前数据可恢复。

## 5. 风险与应对

| 风险 | 应对 |
|---|---|
| 权限字段散落在服务、SQL、RAG 元数据与测试中 | 先全局搜索角色/租户/部门/ACL 标识，建立删除清单，逐模块清零 |
| 旧迁移链与个人版基线冲突 | 归档旧迁移，使用全新基线；旧库不升级 |
| 删除 CR 后版本无触发来源 | 已确定保存前与解析前自动快照，保留 50 个版本 |
| 文本编辑与索引不同步 | 保存、回滚、归档、恢复后都重推索引并等待追平 |
| RAG 提示词残留企业语气 | 统一提示词文件与技能模板，人工抽检问答与精读报告 |
| 前端大范围删页面导致路由/组件断裂 | 按路由树从叶子到根删除，每步 type-check；最后再删无用 API 与 store |
| 文档删除破坏历史追溯 | 先备份再删；历史归档是否保留单独决定 |
| 本机监听误改为公网 | 部署默认绑定 `127.0.0.1`，README 明确风险 |

## 6. 完成定义

本轮“可日常使用”达成条件：

- 能用全新数据库启动个人版，完成 owner 登录。
- 能在一个自然日内完成“导入资料、问答、精读、回滚”的完整闭环。
- 不再需要任何企业角色、部门、共享、ACL 或审批配置才能使用系统。
- 所有构建与核心人工流程通过，剩余问题有明确记录且不影响主流程。
- 企业版文档不再作为个人版当前实现依据，新文档足以指导后续开发与验收。
