## 1. 范围与决策（owner 对齐）

- 首批范围：编辑闭环 MVP —— 版本服务（提交/读/diff/回滚）+ 智能体会话/消息/SSE + L0 只读工具 + L1 编辑自动提交与撤销；L2/L3（dry_run + confirm_token + 待确认卡）后置，UI 保持占位。
- 版本存储：扩展现有 `doc_versions` 快照链，不新建 document/content_blob/version_patch 表；migration 11 为 `doc_versions` 增加 `session_id/message_id/tool_name` 审计列。
- 写后索引：每次 L1 提交全文重切分（沿用 `chunker.SplitParentChild`）、单事务替换 chunk 集并快照，随后 `PublishKnowledgeChange` 等待 ≤5s 转后台，`engine_sync_status` 在工具结果与编辑器可见。
- 运行时复用：现有 ReAct 引擎（`app/internal/agent`）、EventBus SSE、工具注册表、chat `sessions`/`messages`（`agent_steps` 存工具步骤）；migration 11 给 `sessions` 增加 `surface`（`agent` 标记），问答/阅读会话列表默认排除。
- 模型：会话可选，存 `sessions.summary_model_id`，必须为 KnowledgeQA 模型。
- 撤销：版本历史开放任意历史版本回滚（复用现有 `Rollback` 快照恢复）；工具卡提供「撤销本次修改」（回滚到该次编辑的前一版本）。

## 2. 后端实现

### 2.1 迁移 000011（PostgreSQL + SQLite）

- `doc_versions` 增加 `session_id`、`message_id`、`tool_name` 与 `(tenant_id, session_id)` 索引。
- `sessions` 增加 `surface VARCHAR(20) NOT NULL DEFAULT ''` 与 `(tenant_id, surface)` 索引。
- `migration_sqlite_versioned_schema_test` 版本断言 7→11 并补列检查。

### 2.2 版本服务扩展

- `CreateVersionWithAudit`：快照仅包含 `chunk_type=text`（回滚不会把父块/图片块写成文本；代价是回滚丢 parent 扩展，已记录为边界）。
- `CommitAgentContent`：新事务 `ApplyDocContentReplace` = 软删旧 chunk → 插入新 chunk（SQLite SeqID）→ 快照版本 → `engine_sync_status=pending`，仿 `ApplyDocVersionRollback`。
- `CompareVersions` 返回 from/to Markdown；`ListVersions` 返回审计列。
- 版本 API（挂在 `/api/v1/knowledge/:id`）：`GET /content?version_id=`、`GET /versions`、`GET /versions/:version_id`、`GET /versions/compare?from=&to=`、`POST /versions/:version_id/rollback`（写入权限校验 + 回滚后触发入库）。

### 2.3 文档写服务

- `GetDocumentContent`：live 或指定版本；live 由启用 text chunk 按 `chunk_index` 拼接，利用 `start_at/end_at` 去重叠；偏移不一致时返回 `exact=false`。
- `CommitAgentEdit`：校验 KB 写权限、拒绝 FAQ 与解析中文档；`expected_version_id` 冲突拒绝；按标题定位章节（跳过代码围栏、层级/occurrence 消歧；replace/append/prepend 只改直属正文，子章节保留；delete 删除整棵子树）；编辑后全文重切、事务提交、触发入库；返回版本号、上一版本号、变更行数与入库状态。
- `CreateAgentDocument`：同步创建 Markdown 知识文档（复用 `triggerManualProcessingWithOptions(doSync=true, skipEnginePush=true)`）、初始 `agent_create` 版本、触发入库。
- `processChunks` 的 chunk 行构建抽为 `buildChunkRowsFromParsed`，手动处理与 Agent 编辑共用。

### 2.4 会话与运行时

- 新服务 `AgentWorkspaceService`：会话 CRUD（surface=agent、owner 校验、KB 非 FAQ、文档白名单属于所选 KB、模型校验/默认取第一个 KnowledgeQA）、消息列表、`RunTurn`（构建 AgentConfig：MaxIterations 12、6 工具白名单、工具输出 60000 字符、历史 8 轮、上下文窗口按模型；新建只含工作区工具的 registry，不影响 chat agent）。
- 新 `POST /api/v1/agent-workspace/sessions/:id/messages` SSE：先校验 owner+surface 再写 SSE 头；复用 `AgentStreamHandler` 与 `types.StreamResponse` 事件（agent_query/thinking/tool_call/tool_result/answer/complete/error）。
- 隔离：`QueryPaged`/`GetByTenantID`/`GetPagedByTenantID` 默认排除 `surface='agent'`；`AgentQA` 与 `KnowledgeQAFusion` 拒绝 agent 会话。

### 2.5 工作区工具（6 个）

| 工具 | 级别 | 行为 |
|---|---|---|
| `list_documents` | L0 | 按会话 KB/文档范围列文档（文件夹/关键字/条数） |
| `get_document` | L0 | 文档 Markdown + 版本 + 入库状态（截断） |
| `search_documents` | L0 | RAG 检索（限定会话 KB/文档） |
| `extract_knowledge_points` | L0 | 读文档 + 会话模型提炼要点 |
| `edit_document_section` | L1 | 章节编辑 → CommitAgentEdit |
| `create_document` | L1 | 新建文档 + 初始版本 |

工具每次调用校验会话范围；每回合最多 3 次 L1 写入；失败转为 `Success:false` 结果，不抛 Go error。

## 3. 前端实现

- `AgentWorkspace.vue` 全量接真实数据：任务新建/历史/删除、知识库文档树（按文件夹分组、可展开）、编辑器加载 `getKnowledgeContent`、发送 SSE 与消息回放（`agent_steps` → 事件流）、工具卡（运行中/完成/失败 + 输出摘要）、编辑结果条与「撤销本次修改」、版本历史对话框（列表/对比预览/任意版本回滚）、模型选择（会话级，`ModelSelector`）。
- 新 `api/agent-workspace`、`api/knowledge-base/versions` 客户端；`utils/agentWorkspaceStream`（SSE reducer + 历史步骤映射 + 编辑结果提取，node:test 单测）。
- L2 待确认卡保留静态占位并说明下批开放。

## 5. 差距与边界

- L2/L3（dry_run、pending_task、confirm_token、拆分/合并/删除、409 复核）未实现，UI 占位。
- 快照仅 text chunk：回滚不恢复 parent-text 展开元数据；应用侧向量索引不重建（文档问答真值走 YLSW），chunk 全量重切后旧 chunk_id 在复习卡来源/阅读批注中悬空（无 FK，既有边界）。
- 版本 seq 并发仅进程内互斥 + `expected_version_id` 冲突检查；多实例 DB 级竞争留后续。
- 流式中途刷新会丢当前轮 live 流（历史回放正常）；无 live-run/stop/标题生成。
- 生产镜像未重建（沿用 owner 决定，先落源码）。
