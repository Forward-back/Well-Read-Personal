# Agent L2/L3 确认链与回收站（2026-11-28）

> 状态：当前
> 最后更新：2026-11-28
> 关联：[Agent 功能说明](../../02-需求与设计/07-agent/agent功能说明.md)、[当前进度](../当前进度.md)、[Agent 后端 MVP](2026-11-28-Agent后端MVP.md)

## 1. 范围与决策（owner 对齐）

- L3 首批全做：`delete_document`、`restore_document`、`overwrite_document`；L2：`split_document`、`merge_documents`、`revert_document`（回滚同时保留人工入口）。
- 拆分/合并的源文档一律进入回收站；用户在回收站决定恢复或彻底删除；回收站默认保留 30 天。
- Agent 回答与思考全部流式输出（沿用引擎 ChatStream → EventBus → SSE）。
- 人工删除入口（单删/批删）改为进入回收站语义，与 Agent 删除一致。

## 2. 后端实现

### 2.1 迁移 000012（PostgreSQL + SQLite）

- `agent_pending_tasks`：dry-run 任务（风险级、dry_run JSON、base_version、token 哈希/过期/消费、状态、24h 过期、应用版本列表）。
- `doc_lineage`：split_from / merged_from 关系（src/dst 文档与版本、pending_task）。
- `doc_versions.pending_task_id` 审计列。

### 2.2 确认链（agent_pending_service）

- `Plan`：按工具构建 dry-run 计划并落 pending（不写文档、不发 token）；输出 diff 摘要。
- `Confirm`：校验 owner/状态/过期；服务端签发一次性 token（10 分钟、只存 SHA-256 哈希）并立即消费执行；执行事务前复核 `base_version`（不一致返回 409）；成功后写 `applied_version_ids`，失败写 error 并标记 failed。
- `Reject`：仅置 rejected，不写文档。`PurgeExpired`：24h 过期任务标记 expired（每日 housekeeping）。
- 执行语义：split 新建两篇文档（提取章节 + 其余）→ 源文档进回收站 → 两条 split_from lineage；merge 新建合并文档 → 全部源文档进回收站 → 每条 merged_from；overwrite 走 `CommitAgentMarkdown`（全文重切+版本+审计+入库）；revert 走版本服务 `Rollback`（前向回滚，新增 rollback 版本）。

### 2.3 回收站（knowledge_trash）

- 人工删除（`DELETE /knowledge/:id`、`/knowledge/batch-delete`）与 Agent 删除统一为 Trash：软删知识行、移除 YLSW 文档与应用侧向量条目，保留 chunks/文件/标签。
- `GET /knowledge/trash`（kb/keyword 分页，含 `purge_after`）；`POST /knowledge/:id/restore`（清 deleted_at → 重新解析入库）；`DELETE /knowledge/trash/:id`（彻底删除：chunks、标签、文件、行）。
- 每日 housekeeping（启动 2 分钟后首跑，此后 24h）：过期 pending、超过 30 天的回收站文档物理清理。
- Agent L3 restore 同样走该恢复链路；`get_document` 现返回最近 10 个版本（id/标签/来源/时间），`revert_document` 可据此选择目标版本。

### 2.4 工具与提示词

- 工具白名单扩至 12：6 个 L0/L1 + 3 个 L2（split/merge/revert）+ 3 个 L3（delete/restore/overwrite）；L2/L3 全部只做 dry-run，返回 `pending_task_id` + diff + 风险级 + 过期时间。
- 系统提示词补充：L2/L3 预览后必须由用户在待确认卡确认；不得声称已执行；409 时重新读取并预览；拆分/合并源文档进回收站 30 天。

## 3. 前端实现

- 待确认卡接真实数据：风险徽标（L2/L3）、diff 摘要、pending_task_id、剩余有效期、状态（待确认/已执行/已驳回/已过期/执行失败）、确认/驳回；L3 确认弹窗用危险色并展示影响摘要；确认后刷新文档、树与版本；409 提示重新预览。历史消息加载时按 tool_data.pending_task_id 回填真实状态。
- 知识库页顶栏新增「回收站」：列表（删除时间、彻底删除时间）、恢复、彻底删除（二次确认）、分页。
- 删除接口响应从异步任务改为即时 `trashed_ids`，前端删除等待逻辑按文件列表自然收敛，无需改动调用方。
- 工具名与显示标签扩展到 12 个；思考过程与回答在 live 面板实时渲染。

## 4. 验证

- 后端：`go vet ./...` 通过；database、repository、service、agent/tools、handler/session、router、docs 全绿（handler 仅已知环境限制测试失败）。
- 前端：type-check、602 测试、i18n 缺失键 0、生产 build 通过。
- 真实链路（5173 + 热重载后端，迁移 12，306 路由）：
  - SPLIT：Agent 预览卡 → 确认执行 → 生成《网关A-作用》《阅读评测-网关A配置·其余》，源文档进入回收站，split_from lineage 落库。
  - L3 DELETE：预览卡 → 危险确认 → 文档进入回收站；回收站 UI 显示删除/彻底删除时间并成功恢复。
  - OVERWRITE：确认后生成新版本；构造“预览后文档被改动”场景，确认返回 HTTP 409「文档已被修改」，pending 标记失败。
  - REVERT：确认后生成 rollback 版本，内容回到目标版本。
  - MERGE：确认后生成合并文档，源文档全部进回收站，merged_from lineage 2 条。
  - 流式：直连 SSE 单轮收到 402 个 answer 帧、490 个 thinking 帧、6 个工具事件与 1 个 complete 帧。
  - 测试数据已清理（恢复源文档、彻底删除临时文档、删除测试会话、驳回遗留 pending）。

## 5. 差距与边界

- 回收站仅知识文档；知识库本身删除仍为现有语义；「清空知识库」仍走旧的异步销毁流程。
- 回收站清理只移除主文件，提取图片等附属资源依赖既有资源引用计数，不做额外逆向回收。
- pending 过期状态通过确认/轮询发现，不主动推送 SSE 通知；多实例并发仍为单实例假设。
- 彻底删除不清理 `doc_versions` 审计链（保留追溯）。
- 前端仍在 5173 验证，生产镜像未重建。
