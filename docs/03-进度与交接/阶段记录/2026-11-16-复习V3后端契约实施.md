## 1. 结论

按[复习页 V3 设计与实施说明](../../02-需求与设计/复习功能页面优化/优化事项.md) §10 的实施顺序完成第 1 步。后端已切 V3 行为，前端复习页仍是 V2 shadcn 三标签，只完成 API 契约同步；V3 浏览器验收未执行。

## 2. 已实施

### 2.1 迁移

- 新增 `app/migrations/versioned/000003_review_v3_easy.up.sql` 与 SQLite 对应文件：`review_sessions.easy_count`，默认 0；旧会话不反推秒答。
- 迁移版本从 2 升到 3；SQLite 基线 schema 测试同步版本与列断言。

### 2.2 调度与队列

- 评分新增 `easy`：稳定度 ×5、等级 +2，封顶 L6；`remembered` ×3、+1；`fuzzy` ×1.5；`forgot` 重置 5 天、回 L0。
- 删除 `lapses >= 3` 自动暂停。严重卡保持 active，由漏洞级别显示；暂停只来自用户操作。
- 今日队列：总量默认/上限 100，新卡上限 20；到期优先，额度用满不出新卡。
- 暂停卡恢复保留忘记次数、清连续忘记；孤儿重绑来源后转为暂停，不自动回队列；删除卡恢复后为暂停，且无 active 知识来源时转孤儿。

### 2.3 会话

- `POST /review/sessions` 遇到 active 会话且未传 `force_new` 返回 409；`force_new=true` 先放弃旧会话再新建。旧会话已完成日志保留。
- 会话计数新增秒答；统计、会话历史与导出复用同一结构。

### 2.4 漏洞聚合

- 单卡级别按设计 §6.3：严重/警告/观察/健康/暂无数据；只用稳定度、漏答、连续忘记、最近 5 次评分与逾期天数。
- `GET /api/v1/review/heatmap?group_id=`：行=有 active 卡的叶子卡组（非叶子卡组自身挂卡时生成虚拟行），列=标签、来源文档标题或未分类；多标签卡进入多列，分母可重叠。
- 格子返回总卡数、各级卡数、加权强度、簇级别与可点击标记；簇级别取强度分档与最高单卡级别的较高者。
- 返回优先补强（严重/警告前 3）、观察簇数量与一条系统洞察；洞察按严重簇数统计，行优先于列。
- `GET /api/v1/review/clusters/detail?row_id=&column_key=`：簇内卡片、级别、最近评分、建议动作、可用来源与知识库 ID，供重学与回原文。
- 卡片列表、详情与表现接口增加计算字段 `vulnerability`，不落库。

### 2.5 卡片批量与重置

- `POST /api/v1/review/cards/batch`：`delete`、`move`、`add_tags`、`reset`；1–100 张；全量校验后执行，任一卡片不存在或已删除整批失败。
- 追加标签为并集、大小写不敏感去重、单标签 1–32 字、每卡最多 10 个；超限整批失败。
- `POST /api/v1/review/cards/:id/reset`：等级 0、稳定度 10、漏答与连续忘记 0、到期立即；日志、复习次数、统计保留。
- 孤儿卡不参与重置，需先重绑来源。

### 2.6 统计与前端契约

- 保留率 =（想起来 + 秒答）/ 总评分；评分分布、趋势、困难卡、会话历史、导出均含秒答；旧字段保留。
- `frontend/src/api/review.ts` 增加四档评分、漏洞级别、热力图、簇详情、批量、重置、`new_limit`、`force_new` 类型与调用；V2 自选复习入口在 active 会话时先确认再 `force_new`。
- `npm run type-check` 通过。
