### 2.2 设置与外部接入

- 新增 `app/internal/router/routes_settings.go`，设置路由挂在 `/api/v1/settings/*`，只接受 JWT；API Key 网关对未显式声明的路由默认拒绝，机器 Key 不能读取或生成凭据。
- 单 Key 接口：`GET/POST/DELETE /api/v1/settings/api-key` 与 `POST /api/v1/settings/api-key/reset`；使用只读预设，响应只返回掩码，创建/重置时明文只出现一次。创建与重置响应的掩码取自本次明文 token，不再显示 `enc:v1...` 密文前缀。
- Tenant KV 从 `/api/v1/tenants/kv/*` 迁移到 `/api/v1/settings/kv/*`；后端按 key 分发到 web search、提示词、解析器、存储、会话历史、检索、记忆、精读配置。
- 前端 API 客户端已同步迁移：`chat-history.ts`、`memory.ts`、`retrieval.ts`、`web-search.ts`、`collaboration/index.ts`、`reading/index.ts`、`system/index.ts`。

## 6. 风险与已知边界

- 个人版要求全新数据库；企业库字段与迁移链已不兼容，不能原地升级。
- `data/rag/` 仍是本地检索数据目录（gitignore），不要删除；RAG 元数据尚未去企业语义。
- 企业页面虽然不再挂路由，但仍参与前端编译与测试，可能阻塞构建。
- `OWNER_EMAIL` / `OWNER_PASSWORD` 缺失或密码不合规时服务会启动失败；部署前必须配置。
- 文件访问令牌已改为无状态签名，只能靠短 TTL 过期撤销；需要立即撤销时删除资源或轮换 `SYSTEM_AES_KEY`。
- 工作区改动尚未提交；接手前先确认 `git status`，不要覆盖未提交改动。
- `.env`、模型 Key、数据库口令、owner 初始密码不得进入 git、日志与文档；平台 Key 只显示掩码。
- 文档与代码冲突时以当前代码为准；企业版文档只作历史参考，不是当前实现依据。
