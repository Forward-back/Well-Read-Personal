- 复习主路由 `/platform/review` 为 V3；V2 页面、shadcn 组件/依赖与 Tailwind shadcn token 已删除，生成、合并、重绑孤儿、JSON 导出均已移植。不要再引入第二套组件库或恢复 V2 路由。
- `gaze-ui:personal` 当前运行镜像为 `sha256:8e62e552...`（2026-11-19 13:42 +0800），早于 `d892e78f` 视觉对齐与 2026-11-20 UI 设置/背景；需在视觉调整结束后重新 `type-check`/测试/`build` 并重建镜像。`gaze-app:personal` 已于 2026-11-20 重建为 `sha256:57c66ad7...`，包含头像、`first_user_message` 与背景接口，迁移版本 5。
- 浏览器验收脚本在检测到其他 active 会话时会跳过真实 daily 段，避免误操作 owner 正在进行的复习；任何会写入真实调度的脚本必须先确认 active 会话与测试卡归属。
- 软删除恢复：列表只有在显式筛选 `deleted` 时使用 Unscoped；默认状态过滤仍隐藏已删除卡。恢复后状态为 `suspended`，需用户显式恢复复习。
- 真实 LLM 冒烟验证根因、拆分与新角度；根因首调用约 3.9s、325+327 tokens，拆分约 2.7s、350+491 tokens。一次容器 DNS 抖动导致 `SSRF check failed`，后端按设计返回规则回退，重试后成功；浏览器验收中的根因 29ms 是命中服务端 15 分钟内存缓存，真实首调用以 API 断言为准。
- 警告规则改为最近窗口后，历史“曾经忘记一次”的卡可能从警告降为健康；这是刻意修复，不得为了保持旧告警恢复永久 `lapses` 规则。
- 热力图默认只显示 8 行/10 列，超出合并 other；展开上限 50/30，other 不可点。不得把 other 当作完整覆盖，也不得一次性拉全量卡组×文档。真实冒烟已在隔离测试树上验证 9 行/11 列与展开 10 行/12 列；现有真实卡只有 9 张且全部健康。
- 拆分成功后原卡暂停、无 lineage 字段，派生关系只能靠复制来源与标签追溯。
- V3 卡组栏到期角标只统计 active、已复习且到期（含逾期）的卡，不含新卡；新卡额度与队列状态只在任务条显示。
- V3 后端已取消自动暂停：历史已暂停卡不会静默恢复；新评分不再暂停卡，严重卡持续进入队列与热力图。孤儿重绑来源后保持暂停，删除卡恢复后为暂停，均需用户显式恢复。
- V3 迁移 `000003_review_v3_easy` 新增会话 `easy_count`；旧数据秒答按 0 显示，不改写旧报告；头像迁移 `000004_user_avatar_data` 与背景迁移 `000005_user_backgrounds` 已应用。升级前备份 PostgreSQL、SQLite 与必要数据卷。当前 `schema_migrations` 为 5、dirty=false，最近迁移前备份为 `backups/wellread_pre_backgrounds_20261120.dump`。
- 上传背景原图存 `app_data-files` 卷的 `backgrounds/<userID>/`，不压缩、单张 ≤10MB、最多 10 张；删除用户或重建该数据卷会丢失上传背景。内置壁纸随前端包发布，不可在界面删除。
- V3 热力图允许多标签卡进入多个簇，各列分母重叠，百分比不可相加；界面必须用 tooltip 说明总卡数与重叠规则，避免误读。
- V3 簇级别与加权强度可能不一致：单张严重/警告卡被新卡稀释时强度低但级别仍高；界面必须同时显示强度数字与级别，不能让级别被稀释隐藏。
- V3 取消自动暂停后，严重卡会持续出现在队列与热力图；这是刻意设计，用于保持漏洞可见，不得改回静默暂停。

- 平台壳层最小宽度 600px；移动端（<600px）不在当前范围。
