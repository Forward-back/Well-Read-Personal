## 5. 风险与已知边界

- 复习页前端仍是 V2 shadcn-vue 实现，但后端已切 V3 契约；V2 只发送三档评分，自选复习遇 active 会话已加确认并传 `force_new`。V3 骨架在临时路由 `/platform/review-v3`，不进入侧栏；热力图、卡片、统计与复习模式仍是占位，不得当作已上线。切换主路由前 V2 继续服务，且不得新增 shadcn 组件。
- V3 卡组栏到期角标只统计 active、已复习且到期（含逾期）的卡，不含新卡；新卡额度与队列状态只在任务条显示。
- V3 后端已取消自动暂停：历史已暂停卡不会静默恢复；新评分不再暂停卡，严重卡持续进入队列与热力图。孤儿重绑来源后保持暂停，删除卡恢复后为暂停，均需用户显式恢复。
- V3 迁移 `000003_review_v3_easy` 新增会话 `easy_count`；旧数据秒答按 0 显示，不改写旧报告；升级前备份 PostgreSQL、SQLite 与必要数据卷。当前部署尚未重建，迁移版本仍为 2。
- V3 热力图允许多标签卡进入多个簇，各列分母重叠，百分比不可相加；界面必须用 tooltip 说明总卡数与重叠规则，避免误读。
- V3 簇级别与加权强度可能不一致：单张严重/警告卡被新卡稀释时强度低但级别仍高；界面必须同时显示强度数字与级别，不能让级别被稀释隐藏。
- V3 取消自动暂停后，严重卡会持续出现在队列与热力图；这是刻意设计，用于保持漏洞可见，不得改回静默暂停。
- 复习页视觉验收仍未通过；TDesign 重写后必须由 owner 实机或截图确认，自动化验收不能代替。
- 平台壳层最小宽度 600px；移动端（<600px）不在当前范围。
- 个人版要求全新数据库；旧企业库不能原地升级。升级前备份 PostgreSQL、`data-files`、外部 MySQL 与 `data/rag/faiss_index.bin`。
- `RAG_DATA_DIR`/`LOCAL_MODELS_DIR` 必须正确挂载；`data/rag/` 不进入 git/镜像，删除后模型与索引需要重建。
- RAG 只接收 App 分块；没有 `chunks` 的 `/ingest` 会 400。不要再恢复 RAG 侧解析/分块。
- RAG 不接收 ACL/部门/密级；范围过滤只有知识库/文档白名单。
- FAISS HNSW 不支持物理删除；大量删除或向量错位后运行 `rebuild_faiss.py`。
- 本地 Docker 构建依赖 daemon `mtu=1400` 与 `--network=host`（docreader/ylsw）；换机器需重新确认。
- Windows 本机 Go 测试可能因 duckdb/gojieba CGO 失败；以 Linux 容器结果为准。
- 直连模式必须配置开启思考的问答模型；未配置时直连不可用。
- MCP 工具面固定 17 个只读工具；不要新增写工具、模型工具或租户/共享空间工具。
- `.env`、模型 Key、数据库口令、owner 初始密码不得进入 git、日志与文档；单 Key 只显示掩码。
- UI 组件统一 TDesign，不再启动其他页面的 shadcn 迁移；复习页只作为 V3 页面结构与漏洞交互的参考实现，不以其 shadcn 代码为模板。
