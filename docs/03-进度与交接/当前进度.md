## 6. 风险与已知边界

- 个人版要求全新数据库；SQLite 基线已补齐与 PostgreSQL 一致的业务表和列，`embeddings` 仍为 PostgreSQL 专用。
- 镜像构建依赖 Docker Desktop 网络绕过：daemon `mtu=1400`，docreader/ylsw 使用 `docker build --network=host`；换机器需重新确认代理与 MTU。
- 当前 RAG 已切换为学习/复习模板并清理支付检索分支；直连思考模式与多模态图片索引尚未实施（见 TODO 4）。
- 多模态阶段二已实现图片索引与内嵌，但当前库没有图片子块；Markdown 相对路径图片不会被 App 抽取，真实图片需来自 PDF/DOCX/PPTX 解析提取；阶段二验收前不要删除 `data/rag/` 与图片存储。
- 多模态方案允许全部图片入库且内嵌数量不设上限，可能引入图标/装饰图噪声与超长回答；需在 10 题验收中评估并回调。
- 技能已收敛为纯提示词型：`.md` 上传、在线撰写、编辑、启停与问答注入可用；沙箱脚本技能未实现，相关后端安装接口与表保留但不展示。
- 精读依赖租户 `reading_model_id` 与模型思考控制；当前已把 `deepseek-flash` 的思考控制从 `none` 改为 `thinking_type` 并设为精读模型，换模型或重置库后需在「设置 → 模型与引擎 → 精读模型」重新配置。
- 修改模型思考控制后，精读模型下拉只在该分区重新挂载时刷新；不刷新时可能仍显示旧列表。
- 全量 Forward-Blog 代码同步超过 5 分钟：当前实现逐文件同步 RAG ingest，BM25 每次全量重建；库较大时请求易超时，后续需批量化或异步化。
- `data/rag/` 仍是本地检索数据目录（gitignore），不要删除；RAG 索引元数据仍含文档级 `org_name/product_name/doc_type`，属文档属性，不是租户权限。
- `docs/01`/`02`/`05`、根 README、子系统 README 与 Swagger 已重写；历史阶段记录与 `docs/04` 保留企业版原貌，只作追溯。
- `OWNER_EMAIL` / `OWNER_PASSWORD` 缺失或密码不合规时服务会启动失败；部署前必须配置。
- 文件访问令牌已改为无状态签名，只能靠短 TTL 过期撤销；需要立即撤销时删除资源或轮换 `SYSTEM_AES_KEY`。
- 当前工作区干净；`.env`、`data/rag/`、`app/packages/protoc-*.zip` 为本地文件，不进入 git。
- `.env`、模型 Key、数据库口令、owner 初始密码不得进入 git、日志与文档；平台 Key 只显示掩码。
- 文档与代码冲突时以当前代码为准；企业版文档只作历史参考，不是当前实现依据。
