# 精读 Agent 优化需求

> 状态：规划
> 最后更新：2026-11-22
> 目标读者：产品、开发、测试
> 关联：[交互式精读](../交互式精读.md)、[精读agent开发方案](精读agent开发方案.md)、[ADR 0010](../../../06-架构决策/0010-精读agent采用四段流水线与双模型分层.md)、[复习卡与间隔重复](../../04-复习/复习卡与间隔重复.md)、[当前进度](../../../03-进度与交接/当前进度.md)

## 1. 为什么做

现有精读已经不是“一次吞全文再总结”：后端按窗口推进，强制 quote 逐字校验，校验失败由代码检索补证，并用步数与 token 预算限制运行。继续补页面的价值已经低于补引擎。

当前缺口集中在四处：

1. **没有结构预读**：进入逐章循环前没有全文骨架与论证地图，模型只能边读边猜全文结构。
2. **交互密度过高**：每轮可提出 2–4 个问题，用户容易被连续打断；缺少“先陈述再提问”和安静模式。
3. **记忆不完整**：只保存结论、术语、未决与矛盾的局部摘要，没有用户理解档案、跳过信号与任务预算的稳定蒸馏。
4. **学习闭环断开**：读完后没有自测遍，精读成果不能稳定转成复习卡。

结果可能是“读完了、产出了笔记”，但没有证明用户读懂，也没有把读懂的内容带入长期复习。

## 2. 目标与成功标准

P0 目标：把精读从“逐窗口结构化输出”升级为“四段流水线 + 用户理解状态 + 自测出卡”的闭环，并允许抽取与综合使用不同模型。

成功标准：

- 结构预读能给出每节一句话论点与知识类型，用户可在计划确认时看到。
- 逐章循环每章最多一次提问；理解陈述确认属于低门槛确认，不计入提问预算。连续跳过两次后自动进入安静模式。
- 每轮引用仍必须通过机械校验；无证据内容不进入结论。
- 运行结束后形成跨章综合结论、矛盾与自测题。
- 自测题可预览、勾选并手动导入复习 V3，不自动建卡。
- 抽取模型可不支持 thinking；综合模型必须支持 thinking；两个角色均有回退路径。
- 精读评测集可产出三个指标：quote 命中率、关键结论召回率、自测题有效率。P0 验收要求 quote 命中率不低于 95%，关键结论召回率不低于基线，自测题有效率不低于 90%。

## 3. 使用方式

1. 用户在创建配置中选择文档、深度与阅读目标，生成阅读计划。
2. 系统先运行结构预读，计划确认卡显示章节骨架、每节一句话论点与知识类型。
3. 用户确认后进入逐章循环：系统安静读取，先给本轮理解陈述；满足出题条件时最多抛出一个问题。
4. 用户确认、纠正或跳过陈述；系统把结果写入知识记忆与用户理解档案，再进入下一章。
5. 全部章节完成后进入全局综合：重建论证链、检查跨章与跨文档矛盾、定稿术语。
6. 综合完成后进入自测遍：按章节生成带原文引用的自测题。
7. 用户查看阅读报告，打开自测题预览，选择卡组与题目后导入复习 V3。

## 4. 业务规则

### 4.1 四段流水线

- **结构预读**：读取目录、标题、摘要与图表标题，产出每节一句话论点与知识类型；不写结论，不生成复习卡。结构结果写入阅读计划，作为后续检索与提问的导航。
- **逐章循环**：按章节或标题边界切窗口，不按固定 token 数硬切。每章产出理解陈述、结论、术语、未决问题、矛盾与至多一个提问；全部证据必须带 chunk 锚点。
- **全局综合**：仅在全部章节读完后运行。使用综合模型重建论证链，检查跨章与跨文档矛盾，合并重复结论，定稿术语；不新增无证据结论。
- **自测遍**：基于已确认结论、章节要点与证据生成自测题；答案必须能由证据支持，题目必须可独立回答。自测题先进入预览，不自动写入复习。

### 4.2 交互与节奏

- 顺序固定：先陈述，后提问；用户未确认当前理解前不升级问题。陈述确认不占提问预算。
- 出题需同时满足至少一个信号：概念易混淆、前后表述不一致、与用户填写的阅读目标相关。
- 快速档每章 0 问；标准档与逐条档每章最多 1 问。深度通过窗口大小、章节数量与是否运行收束环节体现，不提高单章提问上限。
- 连续跳过两次后，当前章起进入安静模式：只产陈述与笔记，不再等待确认；后续章节不追加问题。跳过是节奏信号，不得反复追问。
- 判定由综合模型完成，必须引用原文给出增量信息，不使用“对/错”作为唯一反馈。
- 暂停可恢复；停止为终态，保留笔记、报告与自测题。

### 4.3 记忆与状态

运行内维护三类记忆，每轮结束蒸馏后持久化：

| 记忆 | 内容 | 用途 |
|---|---|---|
| 知识记忆 | 术语、已确认结论、矛盾、章节要点 | 下一轮提示词与综合遍 |
| 用户理解档案 | 每章确认率、错答点、连续跳过、被驳回结论 | 安静模式、复测与自测难度 |
| 任务记忆 | 阅读目标、当前章节、剩余预算、深度档位 | 进度、预算与恢复 |

只把蒸馏态带入下一轮；文档原文与完整对话不得常驻上下文。

### 4.4 引用与失败

- 引用必须指向本轮窗口或检索返回的 chunk；quote 必须逐字包含于 chunk 内容。
- quote 校验失败时由代码触发检索补证，而不是依赖模型自行决定“再搜一下”。
- JSON 输出必须通过 schema 校验；失败重试一次，再失败标记该轮降级并保留可观察错误，不得静默丢弃。
- 步数与 token 预算仍是硬顶；达到任一上限即停止并保留已产出的内容。

### 4.5 模型角色

- **抽取模型**：负责结构预读与逐章抽取；允许非 thinking，可使用便宜快模型。
- **综合模型**：负责全局综合、问题判定、矛盾裁决与自测判定；必须支持 thinking。
- 两个角色均未配置时回退现有精读模型；只配置抽取角色时，综合角色回退现有精读模型。
- 旧运行继续使用创建时快照的模型；不因设置变化强制迁移。

### 4.6 自测与复习

- 自测遍按章节生成 2–4 道题，每题包含问题、答案、解析与来源证据。
- 单次运行最多 20 道题进入复习预览；其余保留在报告中，不自动导入。
- 用户选择卡组与题目后手动导入；导入复用复习 V3 的查重、吸收与来源规则。
- 被驳回的结论、被用户标注为错误的理解、没有证据支持的题目不得进入自测预览。

### 4.7 边界

- 仍为单 owner；只使用 owner 自己的文档，不引入 ACL、部门、共享或审计。
- 检索范围固定为本次选中文档；跨文档综合只使用选中文档集合，不放开全库。
- 精读仍不与普通问答共享可执行工具；保留 `grill-with-docs` 口径，但只使用其提问原则，不作为完整运行时 skill。
- MCP 工具面保持 17 个，不新增精读读取工具。
- 不引入 LangChain、LlamaIndex、AutoGen 或其他 agent 框架；继续使用 Go 侧状态机与结构化输出解析。

### 4.8 P0 非目标

原文批注层、费曼自述、概念实体层、论证链 Mermaid、目标驱动与新颖度过滤、版本 delta 深读、遗忘驱动重读、跨运行读者画像、MCP 读取工具、Redis 嵌入缓存均不进入 P0。优先级见 §8。

## 5. 界面意图

- **计划确认**：在现有计划卡中增加结构骨架、每节一句话论点与知识类型；用户确认后才开始逐章阅读。
- **工作台**：保持现有三栏与阅读流；问题区每章最多一个提问；安静模式用状态标签提示“本章只记录笔记”，不新增阻塞弹窗。
- **阶段确认**：继续使用理解陈述与确认/纠正/跳过；确认结果进入用户理解档案。
- **报告**：保留摘要、已确认结论、未决问题与矛盾；新增自测题入口与“导入复习”预览。
- **设置**：在“模型与引擎”的精读配置中提供抽取模型与综合模型两个选择；现有单精读模型作为回退项，不删除。
- **视觉**：沿用 [ADR 0009](../../../06-架构决策/0009-精读工作台改用Notion极简与莫兰迪语义点缀.md) 的精读页面级语言，不新增第二套视觉规范。

## 7. 验收

- 结构预读结果在计划确认卡可见，包含全部章节的一句话论点。
- 标准档逐章运行每章最多出现一个问题；连续跳过两次后不再出题。
- 引用校验失败时仍触发检索补证；无证据结论不进入报告与卡片。
- 全部章节完成后生成综合结论与自测题；自测题可预览、选择并成功导入复习卡组。
- 抽取模型为非 thinking 时可完成结构遍与逐章抽取；综合模型缺失时不静默降级为无思考综合。
- 旧 `state_version=2` 运行可继续完成，不被新引擎中断。
- 评测集跑出 quote 命中率、结论召回率与自测题有效率，并记录基线。
- 前端 `type-check`、测试、`build` 通过；后端 Linux 容器测试与真实模型冒烟通过；owner 完成精读流程签收。

## 8. 优先级

### P0：引擎闭环 MVP

1. 结构预读与计划骨架。
2. 逐章单交互点、安静模式、用户理解档案与任务记忆。
3. 全局综合遍与综合模型。
4. 自测遍、复习预览与手动导入。
5. 抽取/综合双模型配置与回退。
6. 严格 schema、失败降级与可观测状态。
7. 评测集与三指标基线。

### P1：读者在环与报告深化

1. 费曼自述：用户复述，综合模型对照证据评分并给出遗漏与错误。
2. 原文批注层：选区分块、批注持久化、下一轮注入与卡片来源。
3. 报告论证链：claims → evidence → 反驳的 Mermaid 图。

### P2：知识网络与学习调度

1. 概念实体层：概念与文档、结论的关联。
2. 目标驱动选段与新颖度过滤；同文档多版本只深读 delta。
3. 遗忘驱动重读：从复习漏洞反推重读章节。
4. 跨运行读者画像与难度调节。
5. 精读嵌入缓存落 Redis。
6. 引用追踪与批量入库（需单独立项）。

MCP 精读读取工具不纳入路线；如未来需要，先修订“固定 17 工具”硬规则并单独写 ADR。
