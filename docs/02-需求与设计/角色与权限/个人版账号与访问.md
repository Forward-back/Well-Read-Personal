# 个人版账号与访问

> 状态：当前
> 最后更新：2026-11-04
> 目标读者：开发、测试、运维

## 1. 为什么只有 owner

个人版是一人使用的本地知识工具，不存在“不同用户看到不同知识”的需求。系统只保留一个 owner 账号与一条内部工作区；删除角色、成员、部门与资源授权，避免把组织权限模型带进个人场景。

## 2. 账号初始化

- 首次启动读取 `OWNER_EMAIL` / `OWNER_PASSWORD`。
- 缺失、邮箱格式错误或密码不合规时启动失败，不创建默认弱口令账号。
- 已存在账号时跳过创建；不会因环境变量变化覆盖密码。
- 没有注册页、邀请、OIDC、工作区 onboarding 或多账号切换。

## 3. 登录与会话

- 只支持邮箱 + 密码登录。
- 登录响应与 `/auth/me` 返回用户与内部 tenant；不返回角色、membership 或能力码。
- 前端登录后进入问答页；未登录访问业务路由跳 `/login`。
- 设置页支持修改密码；密码变更后旧会话需重新登录。
- 连续失败登录可有限流，但不引入复杂账号锁定流程。

## 4. 单只读 API Key

- 位置：设置 → 外部接入。
- 只有一把有效 Key；重复创建返回 409，需要换 Key 时使用重置。
- 权限固定为只读：检索、问答、读取 Agent、会话历史；创建/读取/列表/删除自己的会话属于 `chat` 能力。
- 明文只在创建/重置时显示一次；之后只显示掩码，可随时撤销。
- 不绑定知识库白名单、能力选择或部门上下文。

## 5. MCP 访问面

- MCP 只暴露 17 个只读工具：知识库/文档/分块读取、混合检索、会话与问答、Agent 读取、Gaze 读取。
- 写入、删除文档、建库、模型管理、租户与共享空间工具已从 MCP 删除。
- `delete_session` 保留，用于清理 MCP 自己创建的会话。
- 网络传输必须配置 `MCP_SERVER_AUTH_TOKEN`；本机优先 stdio。

## 6. 安全边界

- 后端是唯一安全边界；前端隐藏按钮不是授权。
- 内部 tenant 与 owner 身份来自认证中间件，不信任请求体或查询参数。
- 未在 API Key 白名单声明的路由，机器 Key 一律拒绝。
- 服务默认只监听本机；对外暴露需自行承担 TLS、反向代理与访问控制。
- 密钥与口令只来自环境变量，不写数据库、日志或文档。

## 7. 验收

- 空库启动可用环境变量创建唯一 owner，错误配置启动失败。
- 登录后看不到角色、部门、邀请、工作区切换。
- 设置页能生成、查看掩码、重置、删除单 Key。
- 单 Key 可调用只读 MCP 工具；写工具不存在；撤销后立即失效。
- 业务接口不接收 `acl_scope`、部门、角色或能力参数。
