# WellRead Agent 功能说明

> 状态：规划
> 最后更新：2026-11-26
> 目标读者：产品、后端、前端、Agent / RAG 开发者
> 关联：[Agent 原型](Agent插件VSCode原型.html)、[Markdown 版本控制技术方案](MD文档版本控制_技术方案.md)、[系统总览](../../01-项目总览/系统总览.md)

## 1. 定位与边界

「智能体 / Agent」是 WellRead Personal 的第 7 个一级功能，面向**知识库 Markdown 文档的对话式编辑**。它不是普通问答的替代，也不是精读 agent：

- 问答：检索并回答，不直接修改文档。
- 精读：固定 `grill-with-docs`，围绕阅读计划推进。
- Agent：在独立工作台中读取文档、理解结构、生成修改建议，按风险级执行写入并落版本；可撤销、可回滚。
- MCP 工具面保持 17 个不变；Agent 不新增外部工具，也不走精读链路。
- 个人版单 owner；内部 tenant 只作归属。不引入角色、ACL、共享空间、协作者或分支合并。

首版只处理 Markdown（`.md`）文本，不处理二进制、图片重写或文档结构以外的知识库管理操作。

## 2. 入口与页面结构

左栏新增第 7 项：

- 中文：智能体
- 英文：Agent
- 路由：`/platform/agent`
- 图标：简化机器人/节点图标，沿用左栏图标线与激活态。

Agent 页面使用独立工作台，不再套用 1200px 内容容器；外层仍使用共享壳层（顶栏 + 左功能栏 + 右辅助栏 + 中央应用窗）。

页面自上而下：

1. **48px PageTopbar**：标题「智能体」、当前任务/模型摘要、主题切换、新任务、历史会话、版本历史、折叠对话。
2. **三栏工作区**：
   - 左：当前知识库文档树（250px 基准），展示文件夹、文档、修改标记；底部当前版本摘要。
   - 中：编辑器 / Diff。文档标签、面包屑、行号、插入块、行级增删、版本提示。
   - 右：Agent 对话面板（392px 基准，可拖拽/折叠）。会话头部、角色/范围 chips、消息、工具卡、Diff 预览、待确认卡、输入区。

原型仅表达布局与组件；配色采用全站浅色/深色 token，不使用原型的 VS Code 配色。窄屏（<1100px）先隐藏对话面板并提供展开入口；<760px 文档树收起，编辑器单列。

## 3. 交互模型

### 3.1 任务与会话

- 每次 Agent 对话属于一个任务；同一任务可跨多轮工具调用与多次文档变更。
- 任务保存：标题、目标、当前文档范围、模型、状态、创建/更新时间。
- 会话历史独立于问答历史；问答会话抽屉不展示 Agent 会话。
- Agent 会话与文档版本通过 `session_id` / `pending_task_id` 关联，供审计和回滚追溯。

### 3.2 风险分级

| 级别 | 场景 | 执行方式 |
|---|---|---|
| L0 只读 | 列出文档、读取结构、读取分块、检索、提炼知识点 | 直接执行，不落版本 |
| L1 局部编辑 | 编辑某段落、插入摘要、创建 Markdown 文档 | 执行后自动 commit；通知卡提供撤销（前向 revert） |
| L2 结构变更 | 拆分/合并文档、跨文档回链、批量改写（P1） | `dry_run` 返回 Diff + `pending_task_id`；用户确认后签发 `confirm_token`，`apply_change` 成功才 commit |
| L3 高风险 | 删除、覆盖全文、恢复/彻底删除（P1/P2） | 同 L2，且需要二次确认与明确影响范围 |

**确认规则：**

- Agent 永远不能自行生成或预测 token；token 只在用户确认后由服务端签发，10 分钟一次性有效。
- pending task 默认 24h 过期；过期变 `cancelled` 并在对话中通知。
- 执行前重新校验 `current_seq`；与 dry_run 不一致时返回 409，旧任务失效，Agent 需重新预览/重算。
- L1 撤销通过版本服务生成**前向 revert**，不移动指针、不删除历史。

### 3.3 典型流程

1. 用户打开文档或选择知识库，输入指令。
2. Agent 调 L0 工具读取结构/章节/分块并流式回复。
3. 若为 L1：执行编辑 → 新版本 vN → 编辑器高亮插入块 → 对话卡出现「撤销本次修改」。
4. 若为 L2/L3：先调 `dry_run` → 展示结构化 Diff 与影响范围 → 用户确认 → 服务端签发 token → `apply_change` 执行 → commit → 通知结果。
5. 用户可从版本历史查看每个版本、Diff、作者/来源与 revert 入口。

## 4. 首版工具面（P0）

| 工具 | 级别 | 说明 |
|---|---|---|
| `list_documents` | L0 | 当前知识库文档树与元数据 |
| `get_document` | L0 | 文档全文/结构/版本 |
| `search_documents` | L0 | 知识库检索，返回可引用片段 |
| `extract_knowledge_points` | L0 | 从指定章节提炼知识点，不写库 |
| `edit_document_section` | L1 | 按标题/段落编辑；返回新版本与撤销入口 |
| `create_document` | L1 | 在指定知识库/文件夹创建 Markdown |
| `preview_change` | L1/L2 辅助 | 不落库 Diff 预览 |
| `revert_document` | L2 | 前向 revert 到指定版本（用户确认） |

**P1 后置：** `split_document`、`merge_documents`、跨文档批量改写、文档删除/恢复。原型中的拆分确认卡用于演示 L2 框架，不代表 P0 工具已开放。

## 5. 工具卡与对话展示

工具卡必须包含：

- 工具名与内部函数名；
- 风险级（L0/L1/L2/L3）与状态（运行中/完成/待确认/失败）；
- 输入范围、返回摘要、影响文档与版本；
- L1 的撤销入口；L2/L3 的 Diff 预览、`pending_task_id`、token 状态、确认/驳回/设置过期。

Diff 卡使用行级增删、上下文折叠与统计；点击行可定位编辑器。确认卡必须同时展示「预览所见 = commit 所得」，不能只写“已修改”。

## 6. 版本与编辑器联动

- 编辑器顶部/底部展示当前 `vN` 与未提交标记；Agent 写入后立即刷新版本。
- 版本历史：列表分页、作者/来源（user/agent/system）、op_type、变更行数、时间、任务 ID；不返回全文。
- 版本详情：全文重建、与任一版本 Diff、revert；revert 走 L2 确认。
- L1 撤销与版本历史共用同一 revert 服务；不实现独立“内存撤销”。
- Agent 任务内多步编辑建议合并为单个 commit，避免版本碎片。

## 7. 数据与接口（设计口径）

### 7.1 建议表

- `agent_sessions`：会话/任务头（owner、标题、知识库范围、模型、状态、时间）。
- `agent_messages`：角色、内容、状态、流式元数据、创建时间。
- `agent_tool_calls`：工具名、风险级、参数/结果摘要、状态、关联消息、版本/pending_task。
- `agent_pending_tasks`：`pending_task_id`、工具、dry_run 结果、目标文档/版本、状态、过期时间、确认记录；token 只存哈希/消费状态，不存明文。
- 版本相关表沿用[版本控制技术方案](MD文档版本控制_技术方案.md)的 `document` / `doc_version` / `content_blob` / `version_patch` / `doc_lineage`。

### 7.2 接口分组

- `GET/POST /api/v1/agent/sessions`、`GET /api/v1/agent/sessions/:id`：会话与历史。
- `POST /api/v1/agent/sessions/:id/messages`：发送消息，SSE/流式返回消息、工具卡和 pending 状态。
- `POST /api/v1/agent/pending/:id/confirm` / `reject`：用户确认/驳回；确认服务签发 token。
- 文档读取复用现有 knowledge/chunk API；写入走版本服务 commit 入口。
- 版本接口沿用技术方案 §2.5；Agent 不直接写 `doc_version`，统一经版本服务。

首版不新建独立向量库或模型配置；Agent 复用当前知识问答模型与检索能力，模型选择在 Agent 会话头部显示。

## 8. 页面状态与失败处理

- 空态：未选文档时显示知识库树与输入提示；无历史任务时展示引导。
- 流式：消息流式出现，首 token 前显示运行态；工具卡逐个更新。
- 工具失败：显示错误摘要与重试；不静默吞错，不伪造成功。
- 待确认：固定确认卡；过期/驳回有明确状态；执行中禁止重复提交。
- 版本冲突：409 提示“文档已被修改”，提供重新预览；不覆盖他人/其他任务修改。
- 降级：模型不可用或检索失败时保留只读对话，禁止写入并提示配置。
- 删除/撤销：必须能从版本历史回溯；任何 L1 修改都有撤销入口。

## 9. 验收口径（P0）

- 左栏 7 项导航、`/platform/agent` 可进入；浅色/深色均与全站 token 对齐。
- 三栏工作台可折叠聊天、可调整聊天宽度；编辑器 Diff 与对话工具卡在窄屏可用。
- L0 工具直接执行；L1 编辑成功产生新版本并出现撤销；L2 预览需确认，确认前不写库，确认后 token 一次性消费并 commit。
- 版本历史可列出、查看 Diff、revert；409 冲突可见并可重新预览。
- 刷新/重进后任务、消息、pending 状态与版本一致；失败有重试，过期任务不可执行。
- 不出现多 owner、角色、ACL、共享空间或 MCP 工具扩展。

## 10. 非目标

- 不做真实 git 仓库、branch、merge commit。
- 不做通用文件管理器、二进制编辑、图片/视频生成。
- 不替代问答、精读或技能页；不共享精读可执行工具。
- 不在首版实现 chunk 指纹复用/增量重切/归档压实；这些按版本方案 P1/P2 推进。
