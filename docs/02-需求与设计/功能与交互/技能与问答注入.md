# 技能与问答注入

> 状态：当前
> 最后更新：2026-11-04
> 目标读者：产品、开发、测试

## 1. 为什么用

技能把常用提示词、操作步骤与脚本资源封装成可复用能力。个人版把技能当作 owner 的个人资产，不再有部门技能、只读技能页或按人授权。

## 2. 使用方式

1. 设置或技能页查看技能目录。
2. 创建/编辑技能：名称、描述、说明、资源包；或从目录安装。
3. 启用/停用、删除技能。
4. 普通问答时在输入栏选择技能；系统按需读取 SKILL.md 与资源。

## 3. 业务规则

- 技能归 owner；没有部门归属、可见范围或授权记录。
- 技能只用于普通问答；精读固定 `grill-with-docs`，两者不共享可执行工具。
- 提问时只注入当前选择且启用的技能；未选择不注入。
- 技能脚本需要 sandbox；Docker sandbox 未启用时相关运行时能力不可用。
- 删除技能不删除已产生的会话或消息。

## 4. 界面意图

- 顶层技能页展示个人技能列表与启停状态。
- 技能编辑弹窗包含基本信息、说明、资源包与脚本；不显示部门授权或共享。
- 问答输入栏的技能选择只列出可用且启用的技能。

## 5. 当前实现与差距

| 项 | 当前实现 |
|---|---|
| 技能目录/创建/编辑/启停/删除 | 已保留 |
| 问答注入 | 已保留 |
| 部门/授权 | 已删除 |
| sandbox | 仅 docker/disabled；e2b/cube 已移除 |

## 6. 验收

- 可创建技能并在问答中选择注入；未选择时不注入。
- 技能页不出现部门、只读或授权入口。
- 精读流程不加载普通问答技能工具。
