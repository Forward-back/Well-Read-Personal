# 交互式精读

> 状态：当前
> 最后更新：2026-11-04
> 目标读者：产品、开发、测试

## 1. 为什么用

问答适合快速查事实；精读适合把一组文档真正读完并形成自己的理解。个人版保留完整精读工作台，但删除共享文档、逐文档 ACL 复核、部门聚合与阅读审计。

## 2. 使用方式

1. 从文档、引用或精读入口选择一组文档。
2. 选择阅读深度（快速/标准/深入），生成阅读计划。
3. 在三栏工作台中逐节阅读：左侧章节与计划，中间原文，右侧问题卡、笔记与报告。
4. 系统按计划自动推进；可停止、恢复、跳节或补读。
5. 完成后生成阅读报告并导出。

## 3. 业务规则

- 精读固定使用 `grill-with-docs` 流程，不共享普通问答的可执行工具。
- 只能使用 owner 自己的文档；没有 shared-in 或 ACL 复核。
- 阅读笔记、问题与报告归 owner；不写入治理或审计系统。
- 导出按实际读取章节统计，不按权限复核结果统计。
- 阅读运行与文档关联；文档删除时相关精读运行失效。

## 4. 界面意图

- 精读页展示运行列表与当前运行；工作台三栏清晰分区。
- 问题卡区分疑问/澄清/验证等类型；笔记可编辑并持久化。
- 报告展示章节覆盖、关键结论与未解决问题；导出入口在报告页。
- 不显示共享成员、部门维度或阅读审计。

## 5. 当前实现与差距

| 项 | 当前实现 |
|---|---|
| 阅读计划与自动推进 | 已保留 |
| 笔记/问题/报告/导出 | 已保留 |

| 真实文档回归 | 待用 `data/rag/Data` 文档执行一次完整精读 |

## 6. 验收

- 可从文档进入精读并生成计划。
- 工作台可完成逐节阅读、记录笔记、生成报告与导出。
- 页面与接口不出现权限复核、部门或审计字段。
