# 交互式精读

> 状态：优化中
> 最后更新：2026-11-21
> 目标读者：产品、开发、测试
> 关联：[精读工作台视觉决策](../06-架构决策/0009-精读工作台改用Notion极简与莫兰迪语义点缀.md)、[界面规范](界面规范.md)

## 1. 为什么用

问答适合快速查事实；精读适合把一组文档真正读完并形成自己的理解。个人版保留完整精读工作台，但删除共享文档、逐文档 ACL 复核、部门聚合与阅读审计。

## 2. 使用方式

1. 从文档、引用或精读入口选择一组文档。
2. 选择阅读深度（快速/标准/深入），生成阅读计划。
3. 在三栏工作台中逐节阅读：左侧章节与计划，中间原文，右侧问题卡、笔记与报告。
4. 系统按计划自动推进；可停止、恢复、跳节或补读。
5. 完成后生成阅读报告并导出。

## 3. 业务规则

- 精读固定使用 `grill-with-docs` 流程，不共享普通问答的可执行工具。
- 只能使用 owner 自己的文档；没有 shared-in 或 ACL 复核。
- 阅读笔记、问题与报告归 owner；不写入治理或审计系统。
- 导出按实际读取章节统计，不按权限复核结果统计。
- 阅读运行与文档关联；文档删除时相关精读运行失效。

## 4. 界面意图

- 精读页采用 Notion 简洁风与莫兰迪淡色高亮，仅本页使用低圆角、发丝线与留白分区；品牌绿只承担主行动、进度与选中。
- 工作台三栏：左侧章节目录按标题级别生成树（文档名为根，二级标题、三级标题逐级展开，重复标题合并）与本会话摘要；中栏阅读流（思考链路、本轮结论、行内问题、阶段理解确认、矛盾卡）；右侧按类型展示笔记。进入工作台自动全屏，配置视图保持普通窗口。结论正文使用编号角标，来源在结论下列出，不内联长标题。
- 页头提供工作台/创建配置切换、进度、导出、报告、暂停与停止；原文从右侧抽屉查看，抽屉最大为页面宽度的一半，可拖拽调宽；原文直接复用知识库全文的 `DocumentPreview` 渲染，Markdown 与可访问图片按同一管线显示，引用角标打开抽屉。
- 创建配置支持跨知识库选文：文档选择为文件树（知识库 → 文件夹 → 文档），搜索框默认搜全局；已选文档在下方实时列出并可移除。另提供目标模板与确定性预估，并可保存、重命名、载入与删除多份草稿。
- 问题卡提供三份不同视角候选答案与一份推荐，用户也可自写；提交后由精读模型判定，失败时保留答案可重试。
- 阶段理解确认只影响当前轮笔记；纠正会在下一轮生效。术语与结论可确认、编辑、驳回与恢复。
- 不使用共享成员、部门维度或阅读审计；不出现角色与权限复核文案。

## 6. 验收

- 可从文档进入精读并生成计划。
- 工作台可完成逐节阅读、记录笔记、生成报告与导出。
- 页面与接口不出现权限复核、部门或审计字段。
