# 保留单基线并新增增量迁移

## 背景

个人版把 PostgreSQL 与 SQLite 的迁移链收敛为单个 `000000_init`，并要求全新数据库启动。复习卡需要新增卡组、复习卡、卡片来源与复习记录四类表；本地已经有知识和复习数据，不能靠修改 `000000_init` 让旧库获得新表。若为此重置数据库，会把个人知识库与本地验收数据一起清空。

## 决策

1. `000000_init` 视为冻结基线，不再承载新功能表。
2. 后续 schema 变更按顺序新增 `000001_*`、`000002_*`，PostgreSQL 与 SQLite 各维护一份，并各自提供 down 迁移。
3. 现有数据库原地升级：启动时执行未应用的增量迁移；全新数据库先执行基线，再执行全部增量。
4. 迁移测试断言最新版本号与目标表/列存在，不再断言版本恒为 0。
5. 涉及数据迁移或删除列的版本，升级前必须先备份；文档记录备份与回滚步骤。

## 考虑过的替代方案

- **继续修改 `000000_init` 并重置数据库**：保持单文件简单，但每次加表都要清空本地数据，不可接受。
- **按版本拆分多个基线**：适合多环境初始数据差异，但个人版只有一个运行形态，增加维护面。
- **把新表放进启动时 AutoMigrate**：绕过版本记录与回滚，无法审计 schema 变更，与现有迁移机制冲突。

## 后果

- 迁移目录会逐步累积文件；单基线文档口径需要改为「冻结基线 + 增量迁移」。
- 每次 schema 变更都要同时维护 PostgreSQL、SQLite、测试断言与 down 路径。
- 首个使用该决策的功能是复习卡，迁移编号从 `000001` 开始。
