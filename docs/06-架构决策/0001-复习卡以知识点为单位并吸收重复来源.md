# 复习卡以知识点为单位并吸收重复来源

## 背景

对话式学习会反复问同一概念。如果每次自测题都新建卡片，卡片量会随对话次数线性增长，管理页很快不可用；如果只在来源知识库内自动分组，又无法表达「考研 / 数学 / 高数」这类学习结构。需要先确定卡片身份、归属与查重范围，数据模型和界面都依赖这三个决定。

## 决策

1. 一张复习卡代表一个知识点，可挂多条来源。保存时检测到同一知识点，默认「吸收」为已有卡的新来源，不新建卡片；调度记录只有一份。
2. 一张卡只属于一个卡组节点。卡组是多层树，用于组织与复习范围；跨主题用标签，不用多卡组归属。
3. 查重在租户内全局进行，跨卡组生效。检测分三层：规范化哈希、题干字符三元组相似度、题干向量余弦相似度；向量只与同一 embedding 模型比较，模型缺失时退回文本层。

## 考虑过的替代方案

- **每次保存都新建卡片**：实现最简单，但卡片量随对话膨胀，与「重复内容不应变成重复卡片」的目标直接冲突。
- **按来源知识库自动分组，不建卡组**：零维护，复用现有结构，但无法表达学习计划中的主题层级，用户反馈找不到卡片。
- **一张卡属于多个卡组**：组织灵活，但到期队列、今日任务与统计会在卡组间重复计数，调度语义复杂。
- **仅同卡组内查重**：保留「错题集」等独立副本，但跨卡组重复会持续增长，与全局去重目标冲突。

## 后果

- 数据模型需要卡组树、卡片来源与复习记录；每张卡必须属于一个卡组，且至少有一条知识来源。
- 吸收后卡片留在原卡组；跨卡组重复需要用户显式移动，或选择「仍要新建」作为例外。
- 卡组删除必须定义卡片的移动/删除与子卡组重挂规则，不能使用数据库级联删除。
- 向量查重依赖来源知识库的 embedding 模型；跨模型无法比较，只能退回文本相似度。
- 前端需要卡组树、重复对比弹窗、合并操作与来源详情，管理页复杂度高于普通卡片列表。
