# 复习 V3 采用四档评分与漏洞驱动闭环

## 背景

V2 已具备持久卡片、自适应稳定度、每日/手动会话、单卡表现与统计页，但仍有四个结构性问题：

1. 三档评分无法区分「想得慢」与「秒答」，调度信号过粗。
2. 累计 3 次忘记自动暂停会把最反复忘记的卡从队列与统计中移走，恰好隐藏需要补强的漏洞。
3. 今日页只给队列，不告诉用户「哪个知识块弱」；统计页的易忘卡 Top10 也不能定位到可执行的知识块。
4. 每日总量 30 没有独立新卡闸门，长期中断后旧债与新卡会一起挤压当日队列。

V3 的目标是把复习从「按队列翻卡」升级为「看见漏洞 → 进入簇 → 补强或回原文」的闭环。

## 决策

1. 评分扩展为四档：忘记、想得慢、想起来、秒答。秒答稳定度 ×5、等级 +2（封顶 L6）；忘记重置稳定度 5、等级回 L0、次日到期；想得慢与想起来沿用 V2。
2. 秒答独立计数；保留率 =（想起来 + 秒答）/ 总评分次数；历史会话与旧日志的秒答按 0 显示，不反推、不改写旧报告。
3. 取消 `lapses >= 3` 自动暂停。严重卡保持 `active`，由漏洞规则标记；手动暂停与孤儿仍不进入队列。历史自动暂停卡不静默恢复，由用户在卡片页显式恢复。
4. 今日队列 = 到期卡 + 新卡；到期优先，新卡最多 20 张，总量最多 100 张；手动与补强会话不占每日额度，今日完成数只统计 `daily` 会话与旧无会话评分。
5. 单卡漏洞级别由稳定度、忘记次数、连续忘记、最近 5 次评分与逾期天数计算；只评估 `active` 卡，0 次复习为「暂无数据」，不判健康。
6. 漏洞簇 = 卡组 × 列；列优先取标签，无标签回退主要 active 知识来源所属知识库，再无来源归入「未分类」。多标签卡分别计入每个标签列，分母允许重叠。
7. 簇强度按卡级别加权：严重 1、警告 0.5、观察 0.25、健康 0、暂无数据 0 但计入分母；强度按 60% / 40% / 20% 分档，簇级别再与簇内最高卡级别取较高者，避免单张严重/警告卡被新卡稀释后隐藏；无已复习卡时为「暂无数据」灰格。
8. 今日优先补强最多 3 条严重/警告簇；全站最多 3 个簇获得视觉强调，但热力图仍全量着色；观察簇只显示数量摘要。
9. 簇详情主 CTA 为「重学这 N 张」，N = 严重 + 警告卡；观察与健康卡不进入强化会话；行内「回原文」，整簇唯一来源时才提供簇级入口。
10. 会话创建显式区分「继续当前」与「新建」；已有 active 会话时从簇或抽屉发起补强，必须弹层二选一，不得静默返回旧会话；放弃旧会话后已完成日志保留。
11. 卡片批量删除、移动、追加标签、重置调度；全量校验后单事务执行，上限 100 张，任一失败整批失败；删除为软删除，重置只改调度字段，日志与统计保留。
12. 复习页整体改用 TDesign，布局与视觉规则见[界面规范](../02-需求与设计/00-通用与界面/界面规范.md) 与[复习页设计](../02-需求与设计/04-复习/复习页设计.md)。

## 考虑过的替代方案

- **保留三档评分，只改统计展示**：实现成本最低，但「想得慢」与「秒答」仍共享同一调度路径，无法满足细粒度记忆信号的需求。
- **保留自动暂停，把暂停卡另开「补强」入口**：能保留漏洞可见性，但同一张卡在两套队列与状态之间切换，规则复杂且容易让用户误以为卡已删除。
- **簇不重叠，强制单标签归属**：百分比可直接相加，但多主题卡片会被强行归入一个簇，热力图会漏掉真实薄弱主题。
- **前端拉全量卡与日志自行聚合**：实现快，但千卡规模会拖慢首屏，且聚合口径容易与统计页分叉；改为服务端聚合。
- **引入完整 FSRS 并持久化 D/R**：更精确，但需要参数校准、迁移与长期调参，超出个人版维护能力；V3 只用现有字段与最近评分推导漏洞。

## 后果

- 需要新增迁移覆盖秒答与四档会话计数，PostgreSQL 与 SQLite 同步；旧数据必须可读，秒答缺省为 0。
- 新增簇聚合、批量卡片操作、调度重置与显式新建会话接口；评分接口新增 `easy` 与客户端请求 ID。
- 热力图列可能重叠，百分比不可相加；界面必须用 tooltip 说明总卡数与重叠规则，避免用户误读。
- 簇级别可能高于强度分档（单张严重/警告卡提升级别）；界面必须同时显示强度数字与级别，避免把低强度误读为健康。
- 取消自动暂停后，严重卡会持续出现在队列与热力图中；这是刻意设计，用于让漏洞保持可见，而不是重新引入「无限刷同一张卡」。
- V3 已于 2026-11-17 完成并通过真实数据/真实 LLM 冒烟；热力图列回退与行下钻口径见实施补充，当前差距见[复习卡与间隔重复](../02-需求与设计/04-复习/复习卡与间隔重复.md) §12.9。
- 迁移前需备份 PostgreSQL、SQLite 与必要数据卷；删除为软删除，重置不清日志，保证可回滚。
- [ADR 0004](0004-复习V2自适应稳定性与会话报告.md) 中与 V3 冲突的部分标记为历史；自适应稳定度、会话与单卡表现继续有效。
