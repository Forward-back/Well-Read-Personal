# 落地页采用 PostHog 布局语言并替换平台壳层

## 背景

现有平台壳层是草地背景 + 手绘图标 + 左侧六项导航 + 悬浮详情窗，视觉方向由[ADR 0005](0005-UI组件沿用TDesign并停止shadcn-vue迁移.md)定义。owner 希望把 posthog.com 首页的版式语言迁移到 WellRead：布局结构优先，视觉语言其次，背景（米灰底、渐变与纹理）是重点提取对象。

posthog.com 是 React 站点，采集确认其首页为「模拟应用」结构：顶部浮动导航条、左右两侧图标栏、中央圆角应用窗、窗内独立滚动的 reader 长文与演示区。WellRead 是登录后使用的个人知识库工作台。两者信息结构不同，不能逐字复制内容，只能迁移版式与视觉规则。ui-clone-skills 的完整管线面向 React + Tailwind 生成，与「全前端 TDesign、禁止第二套组件栈」冲突，需要明确 skill 的使用边界。

## 决策

1. 新增登录后落地页 `/welcome`：顶层路由、`requiresAuth: true`、不套 platform 壳层；现有左侧导航加入口。默认登录跳转仍为 `/platform/creatChat`，不改入口链路。（已由 2026-11-18 实施补充取代：实际为 `/` 落地页，登录成功进 `/`。）
2. 落地页以 posthog.com 首页为布局参考：Header + Hero + 六个内容分区 + Footer 的整页骨架；文案换成 WellRead 中文内容，由 owner 定稿；不复制 PostHog logo、吉祥物、客户评价与图库素材。
3. 实现路线为 Vue 3 + TDesign Vue Next + 自定义 CSS；Tailwind 只做布局与间距。ui-clone-skills 仅用于采集、提取与视觉对照，不产出、不保留 React 实现，也不使用 React 专属生成与 gates。
4. 字体不引入 RoundHog、Squeak 等品牌/商业字体，改用开源近似字体（正文 DM Sans，展示字 Bricolage Grotesque 候选），按参考站字号、行高、字重与字距校准。
5. 强调色保留 WellRead 品牌绿 `#07c05f`；背景采用 PostHog 米灰系统（基面 `#eeefe9`、次级面 `#e5e7e0`、白色卡片、深墨文字），页面外层使用仓库现有草地素材 `frontend/src/assets/img/app-bg/grass.jpg`；其余颜色从参考站提取后转译为 WellRead 语义 token。
6. 动效与交互按参考站完整还原；Hero 提问框提交后跳转真实问答页并预填问题，不做演示假对话。首版仅浅色主题，暗色后续补齐。（已由实施补充取代：暗色模式保留，落地页不再强制浅色。）
7. 验收采用指标化口径：背景色值、容器宽度、栅格列数与间距、分区留白、字号行高、圆角边框阴影、响应式表现与动效 timing 逐项比对；最终由 owner 目视签收并记入阶段记录。
8. 落地页验收通过后，启动壳层替换：用「顶栏 + 左侧 112px 图标栏 + 右侧辅助栏 + 中央应用窗」替换现有壳层；左栏承载六个功能区，顶栏承载品牌与全局操作，右栏承载帮助与关于等辅助入口。保留现有功能（折叠、设置、GitHub、主题切换、帮助、全屏/退出、命令面板）。旧壳层代码与引用删除，旧手绘图标与背景资源文件保留。
9. 功能详情页（问答、知识库、精读、复习、技能、设置）本期不动，后续逐页单独对齐；过渡期允许新旧两种视觉并存。
10. 采集证据保存在 `tmp/ref/`，该目录不进入 git；蒸馏后的设计 token、动效参数与验收记录写入[落地页设计](../02-需求与设计/落地页设计.md)。

## 考虑过的替代方案

- **用 ui-clone 完整管线产出 React 参考站再人工转译**：保真基线可量化，但 React 产物是一次性消耗品，工期约翻倍，且与 ADR 0005 的单一组件栈冲突。
- **落地页作为 React 子应用上生产**：能复用完整管线与自动 gates，但直接违反全前端 TDesign 与禁止第二套组件栈的规则，并引入双技术栈维护成本。
- **只换背景与配色，保留现有壳层结构**：工作量最小，但没有回应 owner 要求的版式迁移，也无法验证 PostHog 布局的适配性。
- **壳层只做顶部导航**：比完整三段式简单，但采集显示参考站的主导航实际在左右图标栏，顶栏承担次级入口与 CTA；只做顶栏会丢失参考站的核心骨架。
- **落地页公开、替换根路由入口**：更接近真实营销站，但会改动现有登录与默认跳转链路，试点阶段风险高于收益。
- **原样自托管 PostHog 品牌字体与素材**：保真度最高，但涉及第三方品牌字体与商标素材，不适合进入长期产品页。

## 后果

- ADR 0005 的「视觉目标 = TDesign 视觉语言 + 品牌绿」条款被本文部分修订：TDesign 组件栈与「品牌绿用于主 CTA/选中」保留，新增 PostHog 版式语言；修订范围覆盖落地页与共享壳层，详情页在各自批次前仍按[界面规范](../02-需求与设计/界面规范.md)现行条款执行。
- [CLAUDE.md](../../CLAUDE.md) §3 的 UI 条款、[界面规范](../02-需求与设计/界面规范.md) §3/§6 需要同步标注目标视觉与过渡期边界。
- 首版仅浅色；现有暗色主题在落地页强制浅色，壳层阶段是否保留暗色另立决策。
- 壳层改造采用顶栏 + 左右图标栏 + 中央窗的混合导航，不采用「仅顶部导航」方案；落地页与壳层共用同一套骨架。
- 字体替换会带来中文排版差异，需按指标校准并在验收记录中列明偏差。
- 引入 ui-clone 工具链依赖：`agent-browser`、`uv`、`dssim`、ImageMagick 已具备，动效录制需要 ffmpeg。
- 落地页面向已登录用户，不承担 SEO、公开注册与营销追踪职责；页脚只保留产品内入口与版本信息。
- 旧壳层删除后不可回退到旧视觉；删除前需完成新壳层验收并保留提交点，旧手绘资源文件不删除。

## 实施补充（2026-11-18）

- 实际落地为 `/` 落地页；`/welcome` 重定向 `/`，登录成功进 `/`，不再保留 `/welcome` 作为独立页面。
- 全量共享壳层替换完成：旧 `platform/index.vue`、Menu、AppTopBar、AppRightRail、GardenKeys 删除，旧手绘资源保留但不再用于壳层。
- 设置从左栏移除，只保留右栏入口；设置路由作为普通详情页渲染，页面内深链接仍使用设置弹窗。
- 详情页支持顶栏全屏/退出：全屏时隐藏左右栏，窗口紧贴顶栏下沿、左右与顶栏对齐；顶栏下方两角改直角。
- 暖米纸色 `#F7F5F0` 作为浅色详情页与落地窗底色；选中/高亮使用亮绿 `#07c05f`，不再使用深绿 `#067a3d` / `#056a34`。
- 暗色模式保留，落地页不再强制浅色；壳层滚动条视觉隐藏但滚动保留。
- 2026-11-19 已复跑 `type-check`、597 测试与 `build`，并重建部署前端镜像；owner 视觉对齐与详情页逐页改造仍待进行。
